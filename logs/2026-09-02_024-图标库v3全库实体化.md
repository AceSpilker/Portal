# 工作日志 · 2026-09-02 · 024：图标库 v3——全部图标统一可编辑/删除

> 记录人：ZCode ｜ 性质：设计修正（用户反馈：图标库里只有上传的自定义图标能编辑删除，其他都不行，应该都能）

---

## 需求（用户原意）

图标库里只有上传的那一个图标能编辑删除，别的（内置图标）都不行——应该所有图标都可以。

## 设计修正（v2 → v3）

**v2 的问题**：内置图标只存在于前端组件库（代码层面），不入库，天然无法管理；
只有上传的自定义图标进了 `custom_icons` 表——导致"同一个图标库、两套管理规则"。

**v3 方案：图标全库实体化**

| 项 | 设计 |
|---|---|
| 统一实体 | 新表 `icons`：name（显示名，唯一）、source（builtin/custom）、element_name（内置渲染用，唯一）、path（覆盖图/自定义图，唯一）、hidden（内置软删标记） |
| 播种 | 前端首次加载时把 Element 图标名清单 `POST /api/icons/seed` 播种入库（幂等：按 element_name 去重，**已删除的内置图标不会复活**）；组件库升级新增的图标也会被自动补上 |
| 编辑 | 所有图标可改名 + 换图；**改名级联**：引用该图标的应用/分组 icon 字段、常用精选设置同步更新；换图：自定义覆盖原文件（引用不变）、内置首次设置覆盖图（渲染切到图片） |
| 删除 | 被应用/分组引用时 4003 拦截（提示引用数）；内置 = 软删除（hidden，播种不复活）、自定义 = 物理删除并清理文件 |
| 常用精选 | 内置名与自定义路径统一存于 apps.icon_favorites，选择器「常用」区混合渲染 |

## 完成情况

### 后端
- `CustomIcon` → `Icon` 模型重写（source/element_name/path/hidden）；`init_db` 迁移：旧 `custom_icons` 数据自动并入 `icons`（source='custom'）；
- `/api/icons` 重写：GET 列表（hidden 不返回）、`POST /icons/seed`（幂等播种）、POST 新增自定义、PUT 编辑（改名级联 + 换图）、DELETE（引用 4003 保护 + 软删/硬删分流）。

### 前端
- `iconLibrary` store：实体列表 + 播种缺失内置图标；
- `IconPicker` / 设置页图标库网格改为**全库实体渲染**：所有图标单元格悬停都有编辑/删除按钮；编辑弹窗对所有图标开放（改名 + 上传覆盖图）。

## 测试结果

- 后端新增/重写 `test_icons.py` 7 例：播种幂等、上传压方、**改名级联引用**、**软删不复活**（重复播种 seeded=0）、自定义编辑删除、引用保护；**63 passed**，ruff 全绿；
- 前端 lint / vitest(8) / build 全绿；
- 浏览器端到端：294 个图标全部有操作按钮 → 内置 Bell 改名 BellX（应用引用同步）→ 删除被「媒体」分组引用的 Brush 被拦截 → 删除未引用的 BellX 后整页刷新（重新播种）不复活。
