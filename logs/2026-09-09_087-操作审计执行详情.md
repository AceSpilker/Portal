# 087 · 操作审计执行详情：拆列入库 + 后端日志输出 + 面板重构

## 需求原意

用户要求：
1. 每个动作执行完，记录后端**详细的执行日志信息**——现有审计只存 `status=200 45ms`，
   太简；要把日志输出与数据库存储都补上；
2. 动作列里请求类型和调用接口**拆成两列**；
3. 优化审计画面显示。

## 现状说明（回答"现在为什么不够详细"）

中间件此前每条审计只写 `action="POST /api/apps"`、`detail="status=200 45ms"`、IP、UID——
无 UA、无查询串、无独立状态/耗时字段、无错误消息，查询出来也无法按方法过滤。

## 完成情况

### 1. 数据库（models/audit.py + 轻量迁移）

audit_logs 新增 7 列：`method` / `path` / `query`（≤500 字）/ `status` / `duration_ms` /
`user_agent`（≤200 字）/ `error_msg`（≤300 字）。老库经 `init_db` 轻量迁移自动补列，
历史记录新字段为空值。

### 2. 中间件（core/audit_middleware.py 重写）

- 写入全部新字段；`>=400` 时从统一响应 JSON 提取 `message` 存 `error_msg`
  （只收集错误响应体、8KB 上限、截断 300 字；2xx 不落响应体，杜绝敏感回显）；
- **日志输出**：每个被审计请求经 `portal.audit` logger 输出一行
  `audit POST /api/apps -> 200 45ms user=1 ip=…`——2xx=INFO、4xx=WARNING、5xx=ERROR，
  WARNING+ 由 SystemLogHandler 落 system_logs，与日志中心"系统日志"页联动；
- client_ip 与 services/audit 同口径（优先 X-Forwarded-For）。

### 3. 查询 API（api/v1/audit.py）

- items 补 `username`（user_ids 批量联查）与全部新字段；
- 新增 `method` 筛选参数；CSV 导出补 method/path/query/status/duration_ms/error_msg/user_agent 列。

### 4. 前端 AuditPanel 重构

- 列布局：时间 / **方法**（彩色 tag：POST 蓝 PUT/PATCH 橙 DELETE 红 GET 绿，等宽字体）/
  **接口**（等宽字体路径列）/ 详情（手动业务审计显示动作语义、自动审计显示错误消息或摘要）/
  **状态**（2xx 绿 4xx 橙 5xx 红 tag）/ **耗时** / 用户（username，无则 #UID）/ IP；
- **行展开**显示完整执行详情：状态、耗时、查询参数、错误消息、User-Agent；
- 筛选栏新增方法下拉；旧记录（拆列前）从 action "METHOD path" 解析兜底显示；
- api/settings.ts 补 AuditItem 类型与 method 参数；i18n 双语新增 10 键。

## 关键决策

1. 拆列而非 JSON 塞 detail：可索引可筛选（method=），导出即表格；
2. 错误消息只在 >=400 捕获：2xx 响应体可能巨大且无审计价值，4xx message 是排障关键
   且为服务端生成文案，不含回显的敏感输入；
3. 自动审计 action 保留原 "METHOD path" 值不变：旧数据/旧接口兼容零迁移成本，
   展示层做拆分兜底。

## 遗留

- system_logs 联动只收 4xx/5xx（2xx 量大，全落会撑爆 30 天保留窗）——如需全量请求日志
  建议接访问日志组件而非审计表；
- user_agent 未解析设备型号（浏览器版本解析在前端展示价值低）。
