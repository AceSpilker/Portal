# 050 · P14 Flow 自动化表单版(沙箱/触发器/重试/webhook)

## 需求原意

连续开发 7 个阶段的第 4 个:**P14 · Flow 自动化表单版**(M06-1/2/4~10/15~18,5 步)——轻量版 n8n:"触发器→条件→动作"表单编排。

## 完成情况

### 14.1 Flow 骨架(四种触发器)
- 新模型 `flows`/`flow_runs`(契约 §3.7 全字段,webhook_token UNIQUE、steps_log JSON);
- CRUD(A 读 M 写)+ **cron 触发器**:APScheduler CronTrigger,保存/启停/删除即同步 job(`sync_cron_job`),启动时恢复(`restore_cron_jobs`);**webhook 触发器**:随机 token URL,PUT 换类型自动增删 token,`reset-token` 吊销重置;manual 列表运行;**event 触发器**:`notify.dispatch` 挂事件钩子(app_down/app_up/metric_alert/port_down/port_up/flow_failed),system 事件不触发防自激;
- `POST /api/hooks/flow/{token}`(P,token 鉴权):**middleware 增加 `/api/hooks/` 前缀豁免**(契约 §1 既定,外部回调无法做加密信封)。

### 14.2/14.3 动作与条件
- HTTP 动作(method/url/headers/body + **非 2xx 视为失败**进重试)、通知动作(**{payload.x}/{prev.x}/{vars.x} 变量插值**,webhook payload 注入上下文);
- 条件节点:**ast 白名单沙箱**(比较/逻辑/算术/属性/下标/常量;调用/导入/lambda/推导式/未知名全部拒绝,eval 空 builtins),dict 兼容属性访问(_AttrNS),求值错误归 UnsafeExpression;条件不满足 → 跳过后续动作。

### 14.4 运行保障
- dry-run(副作用动作不真正执行,steps 记 would-do)、flow_runs 每步日志、失败重试(retry×retry_interval,attempt 记录)、失败 dispatch flow_failed(P9 出口)。

### 14.5 前端编排页
- `/flow`(nav Flow 启用):列表(启停开关/运行/试运行/历史/编辑/删除,启用排前);编排对话框(触发器四选一 + cron 表达式/事件下拉 + **动作卡增删排序**(条件表达式/HTTP 表单/通知插值)+ 重试参数);历史对话框(每步状态/耗时/日志)。动作添加由 el-dropdown 改为三个直接按钮(dropdown 在 dialog 内 command 失效,见下)。

## 过程中发现并修复

1. **沙箱逃逸面**:dict 的属性访问(`prev.status_code`)在 eval 层抛 AttributeError 未被归类 → `_AttrNS` 包装 + 求值异常统一 UnsafeExpression;
2. **条件语义**:`eval_error` 曾误用 `error` 键导致"条件不满足"被判为执行失败中断后续 → 拆分键名,失败仅由动作错误触发;
3. **HTTP 非 2xx 未判失败**(经代理的 502 被当成功)→ status≥400 记 error 进重试;
4. **webhook payload 未注入变量** → execute_flow 增加 extra_vars;
5. **el-dropdown 在 dialog 内 command 失效**(IAB/EP 兼容,重开/键盘/坐标点击均不触发)→ 改为直接按钮(更直观)。
