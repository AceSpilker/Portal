## 需求（用户原意）

1. 应用图标不要用 emoji——用 Element Plus 自带的大量图标，想办法在系统中选出来、显示出来；
2. 新增应用时「标签」不要让用户自由输入，给出可选的标签选项，且选项可配置；
3. 增加一个「系统配置」目录，左侧二级菜单，各类配置内容分别放到二级菜单页面里配置（为后续所有配置项立好框架）。

## 完成情况

### 1. 图标体系升级：emoji 选项 → Element 图标库

- 后端 `icon_type` 枚举扩展为 `url / upload / emoji / element`（`emoji` 保留用于渲染历史数据，UI 不再提供该选项）；
- 新增 `utils/elementIcons.ts`：引入 `@element-plus/icons-vue` 全量图标（290+，PascalCase 名 → 组件），含名称过滤工具；
- 新增 `components/AppIcon.vue` 统一渲染：url/upload → 图片、element → 图标组件、其余 → 文本兜底；表格与抽屉预览统一走该组件，尺寸受控；
- 新增/编辑抽屉的「图标库」面板：**名称搜索 + 网格点选**（选中高亮），`apps.icon` 存图标名（如 `Monitor`）。

### 2. 标签选项化（配置驱动）

- 设置表新增默认键 `apps.tag_options`（默认候选：媒体/影音/下载/工具/开发/监控/网络/网盘/家庭/工作），启动时自动合并写入存量库，无需迁移；
- 应用表单标签从逗号分隔文本输入改为 **el-select 多选**，候选完全来自系统配置（暂不开放自由创建，选项统一在配置页维护）。

### 3. 系统配置（/settings，二级菜单框架）

- **后端**：`GET/PUT /api/settings`（api-spec §4.12 契约：A 读 M 写）；PUT 走**可写键白名单 + 逐键校验**（未知键 422、tag_options 需非空字符串数组 ≤50、站点名非空等）；
- **前端**：新增 `views/SettingsView.vue`——左侧二级菜单（常规设置 / 应用配置），右侧配置面板：
  - 常规设置：站点名称（保存后侧栏 Logo **立即生效**）；
  - 应用配置：标签候选管理（el-tag 增删 + 保存）；
- 路由 `/settings` 带 `requiresAdmin` 守卫，导航「设置」入口仅管理员可见；`stores/settings.ts` 全局缓存，页面保存后即时刷新消费端。

## 关键决策

1. **图标名而非截图**：element 类型存 PascalCase 图标名，前端动态解析组件渲染——零资源文件、导出导入天然兼容（字符串随 JSON 走）；
2. **emoji 类型保留在后端枚举中**：存量数据仍可渲染，UI 不再提供，避免破坏性迁移；
3. **设置写入白名单**：settings 是全局键值表，白名单 + 逐键校验防止任意键注入，后续 P7.2/7.3、P23 同步配置等按组扩白名单即可；
4. **本次提前落地 P7.1**（dev-plan 已标 ✅，P7 → 🔄）：设置框架是标签选项化与后续所有配置项的地基。
