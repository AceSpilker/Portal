# 073 · 时区显示修复：审计/安全/端口历史由 UTC 直显改为本地时间

## 需求原意

用户反馈"数据库的时区和正常的系统时间的时区好像不太对"——日志中心操作审计里显示 `08:09:36`，而真实操作发生在下午 4 点过。

## 排查结论

**三个时钟（本地 Mac / NAS / 容器）完全一致（CST UTC+8）**，数据库存储约定也没有错：`created_at` 统一存 naive UTC（`datetime.utcnow()`），API 返回 ISO 串并追加 `Z` 后缀，契约自洽。问题在**显示层**：

- 日志中心·操作审计（AuditPanel）的时间列用 `created_at.replace('T',' ').slice(0,19)` 直接切字符串——显示的是 UTC 原值（比本地慢 8 小时）；
- CSV 导出同样导出 UTC 原值；
- 同类裸直显还有两处：安全面板的 agent 最后在线时间、端口监听历史时间戳；
- 系统日志面板 / 通知中心 / 探活卡片 / 端口事件此前就用 `new Date(...).toLocaleString` 正确转换，无此问题（同一页面两类表时区表现不一致，正是用户觉得"对不上"的原因）。

## 完成情况

**显示层统一转本地时间（存储约定不变，仍是 UTC，契约无破坏）：**

| 位置 | 修复 |
|---|---|
| AuditPanel 时间列 | `new Date(iso).toLocaleString('zh-CN', {hour12:false})` |
| AuditPanel CSV 导出 | created_at 列正则替换为本地时间（`sv-SE` locale 输出 `2026-09-08 16:09:36` 格式） |
| SecurityPanel agent 最后在线 | 同上转换（fmtLocal） |
| PortsView 监听历史时间戳 | 复用本页已有 timeLabel |

## 测试结果

- vitest 57/57、build、eslint ✅；
- NAS 实测截图：审计最新记录显示 `2026/9/8 16:44:44`，与当时真实时间（16:44）一致；CSV 导出时间同样转换。

## 关键决策

1. **改显示不改存储**：DB 存 UTC 是正确约定（跨时区/可排序/契约带 Z），问题只在展示；改存储会破坏既有数据与契约；
2. 扫描了全前端 `created_at` 的渲染点，确认除上述 3 处外其余均已转换，一次性清零同类问题。

## 遗留

- `datetime.utcnow()` 弃用警告（065 遗留 #7）仍在，未来 Python 升级前需统一换 `datetime.now(UTC)`——存储值不变，纯 API 更新；
- 其余遗留同 072。
