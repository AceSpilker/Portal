# 072 · 日志中心：全站操作审计 + 系统日志落库与查看

## 需求原意

用户指出系统缺少操作记录画面和日志的数据库表，没有地方能看到操作记录以及日志信息，要求设计并完成。

## 现状分析

系统已有雏形但覆盖与入口双缺：

- `audit_logs` 表 + `GET /api/audit-logs`（分页/筛选/CSV）早在 M01-14/P17.1 落地，但**写入点只有 4 处**（登录、用户管理、Docker 操作、应用批量），改配置/增删应用/通知渠道/Flow 等日常操作全无记录；
- 查看入口**藏在 设置→审计日志**，用户根本不知道存在；
- 服务端运行日志（定时任务异常、HTTP 500 堆栈）只进 docker logs，应用内完全不可见。

## 设计与完成情况

### 后端

| 组件 | 说明 |
|---|---|
| `models/system_log.py` | 新表 `system_logs`：id / level / logger / message(截断 2000) / created_at |
| `core/log_handler.py` | `SystemLogHandler`：WARNING+ 自动入队（定时任务异常、500 堆栈即被捕获），启动/停止关键 INFO 白名单放行，uvicorn.access 等高频 INFO 不入库；`flush_system_logs` 每 10s 批量刷库；`cleanup_system_logs` 每日清 30 天前记录 |
| `core/audit_middleware.py` | `AuditMiddleware`：/api 的 POST/PUT/PATCH/DELETE 自动写 audit_logs——action=`{METHOD} {path}`、detail=`status=200 45ms`；**不落请求体**（杜绝密码等敏感信息入库）；user_id 从 JWT payload 解出（未认证写操作记 NULL，便于发现探测）；登录/刷新豁免（已有手写审计防重复）；独立 Session + 静默失败，审计故障不影响业务 |
| `api/v1/logs.py` | `GET /api/system-logs`：level/关键词/时间范围筛选 + 分页（管理员） |
| `main.py` | 注册中间件（最外层取真实状态码）、挂日志 Handler、启动 flush/cleanup 两个调度任务 |

### 前端

| 组件 | 说明 |
|---|---|
| `views/LogsView.vue` | 新一级页面「日志」（/logs，仅管理员）：操作审计 + 系统日志双标签 |
| `components/SystemLogPanel.vue` | 系统日志面板：级别/关键词/范围筛选、分页、5s 可选自动刷新、级别彩色标签 |
| 侧栏 | AppLayout 新增「日志」入口（管理员可见，位于工具与设置之间） |
| 设置页 | 移除旧"审计日志"菜单项与分支（数据源统一到日志中心，操作审计标签即原 AuditPanel） |
| i18n | nav.logs + logs.* 12 键（zh/en） |

## 测试结果

- 后端：新增 `tests/test_logs.py` 6 例（写操作自动审计、GET 不记录、登录不重复、action 前缀筛选、system_logs 筛选分页+权限、Handler 入队规则）全过；全量 **229 passed / 2 skipped**；ruff ✅；
- **顺带修复测试基建缺陷**：全量套件曾出现 133 连锁失败——根因是登录限流按 IP 计数而 TestClient 所有请求同 IP，test_auth::test_16 的限流用例锁死后级联全部登录用例（此前 065 记录的 flaky 即同一机制）。conftest 新增 autouse 夹具在每个用例前调 `ratelimit.reset("testclient")`，套件恢复稳定；
- 前端：vitest 57/57、build、eslint ✅；
- NAS 实机：日志中心页面双标签渲染正常，操作审计可见自动捕获的写操作（`POST /api/network-profiles/detect status=200 76ms`）与手写 login 记录；系统日志可见落库的 ERROR 行。

## 关键决策

1. **自动审计中间件而非逐点手写**：新模块零成本获得审计覆盖；detail 不落请求体，敏感信息零风险；已有手写点（登录/用户管理等业务语义）保留，两层数据互补；
2. **system_logs 用调度任务刷库而非常驻协程**：常驻协程 + to_thread 在 TestClient 关闭时会孤儿化 aiosqlite 连接导致退出挂起（实测），调度任务与现有 13 个任务同模式、收场干净；
3. **独立一级页面**而非继续藏在设置里：日志中心是运维高频入口，且系统日志与审计是两类数据，页面内双标签组织。

### 追加修复（同日）：右侧内容区纵向溢出

用户实测反馈 /logs 内容区溢出画面。实测定位为**纵向**问题：审计表一次渲染整页数据把面板无限拉高，筛选条与分页被顶出屏幕。

修复：日志页改为**视口高度约束布局**（`.logs-view` 高度 = 视口 - 页头，tabs 卡片 flex 撑满、内部滚动），两个面板筛选条与分页钉死、表格内部滚动。排查中修了三层 CSS 断链：① AuditPanel 的表格外还有一层 `.table-card`（block）未纳入弹性布局；② `.table-fill` 缺 `min-height:0`（flex 项默认不可小于内容高度）；③ LogsView 的 el-tabs 未 flex 化。实测 1600×900 与 1280×800 均零页面滚动、分页常驻可视区。

## 遗留

- audit_logs 暂无自动清理（量小；system_logs 已有 30 天清理）；
- 操作审计暂不记录请求体参数（防敏感信息），后续可做字段白名单级的参数摘要；
- vue-i18n 的 `docker.logs` 键与新 `logs` 顶级段同名不同层级，无冲突。
