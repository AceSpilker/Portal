# 104 · 效率页"文件/下载"页签撑满高度

## 需求原意

用户反馈：效率画面"文件"和"下载"两个页签的画面高度没有撑满，并疑问
"这部分功能你是不是还没做呢"。

## 功能状态澄清（功能早已实现，看到的是"未配置引导空态"）

两个页签均为 dev-plan 已完成步骤，非缺失功能：

- **文件（M11/P16.2，`FilesPanel.vue`）**：白名单目录浏览（面包屑/多根切换）、
  上传（≤70MB base64 密文）、建目录、重命名、移动、删除、下载（密文），
  图片/视频/音频签名直链预览；
- **下载（M12/P16.3，`DownloadsPanel.vue`）**：qBittorrent 速度/任务统计卡、
  任务表（进度条/速度/状态）、磁力与 URL 批量下发、Jellyfin 最近入库海报墙
  （服务端代理）；
- 两个页签均为**管理员可见**；未配置时（文件无白名单目录 / 下载器未启用）
  分别显示"尚未配置文件白名单目录""下载器未启用或未配置"的引导空态 +
  「去设置」按钮——用户看到的正是这个空态，故产生"没做"的观感。

## 完成情况（纯前端样式）

- `FilesPanel`：`.files` 根 `flex:1 + min-height:0`；`.files-body` `flex:1 +
  overflow:auto`（文件多时卡内滚动）；空态卡 `flex:1` 且内容垂直居中；
- `DownloadsPanel`：`.dl` 根（原先**没有任何样式规则**）补 `flex:1 +
  min-height:0 + flex column`；统计卡行 `flex-shrink:0`；任务卡 `.dl-body.grow`
  `flex:1 + min-height:220px`，任务表 `height="100%" + .fill-table` 内部滚动；
  媒体海报墙自然高度（过长时随页面滚动）；空态卡同文件页签处理。

## 测试结果

- 前端：vitest **57/57** ✅、eslint ✅、vue-tsc + build ✅；
- **浏览器实测**（临时实例，未配置白名单/下载器的初始状态）：
  - "文件"页签：引导空态卡撑满至视口底部 ✅；
  - "下载"页签：「下载器未启用或未配置」空态卡撑满至视口底部 ✅；
  - 已配置形态与空态共用同一 flex 规则（列表/表格 `flex:1` 拉伸），
    行为确定性一致；
- 后端未改动。

## 遗留

- 无。

## 补充（104r1，用户反馈"仍没撑满"排查）

- **NAS 部署核实**：线上 `assets/index-E-5lpcB8.css` 已含 `dl-body.grow`/
  `fill-table`/`max(52px` 等本轮规则，`/`与`/sw.js` 均 `cache-control: no-cache`
  ——服务器侧确为最新；
- 用户看到旧样式的原因为浏览器侧：①PWA Service Worker 预缓存为旧 bundle，
  部署后首次加载仍跑旧缓存，autoUpdate 后台换新后需**再刷新一次**（或直接
  Ctrl/Cmd+Shift+R 强刷）；②应用内浏览器残留的 `localhost:5180` 标签是本次
  验证用的本地临时实例（已停止），并非 NAS 服务；
- **已配置形态实测**（本地实例预置 `files.roots` + 启用下载器指向不可达地址）：
  文件页签渲染真实文件表（资料根目录/上传/新建文件夹）且列表卡撑满到底 ✅；
  下载页签统计卡四张 + 任务卡（含连接失败提示与空表）撑满到底 ✅。
