# 067 · 地址输入协议下拉组件（ProtocolUrlInput）

## 需求原意

所有需要输入地址的地方，前面的 `http://` / `https://` 等协议前缀不要让用户手打，设计成下拉列表直接选择。

## 现状分析

全站盘点出 **10 处**需要输协议地址的输入框（6 个文件）：

| 位置 | 字段 |
|---|---|
| 应用表单（AppsManageView） | 访问入口地址（动态多行）、图标 URL、抓取图标目标站、文档链接 |
| 系统设置（SettingsView） | Logo URL、下载器地址、媒体服务器地址 |
| AI 设置（AiView） | 提供方 Base URL |
| 通知渠道（NotifyPanel） | webhook/wecom/dingtalk/feishu 的 url、Bark/ntfy 的 server（动态 schema 渲染） |
| Flow 表单/画布（FlowView/FlowCanvas） | HTTP 动作 URL |

不适用（无协议语义，保持原样）：SSH/Redis 主机、隧道远端主机、端口监控目标（host:port）、模板主机名、证书监控域名列表。

## 完成情况

**已实现并部署。**

1. 新增共享组件 `components/ProtocolUrlInput.vue`：`el-input` 前置 `el-select` 协议下拉（默认 https:// 与 http://，可通过 props 扩展）；
   - 粘贴/手输**带协议**的完整地址 → 自动吞掉前缀并切换下拉选中项；
   - 回显已有数据自动拆分协议与地址；
   - 地址为空时产出空串，不会保存"光秃秃的协议前缀"；
   - `inheritAttrs:false` 透传 size/clearable/style 等属性到内部 el-input，替换成本最低；
2. 纯函数 `utils/protocolUrl.ts`（splitProtocol / joinProtocol / stripProtocol）+ 单测 5 例；
3. 10 处替换全部完成（应用 4 + 设置 3 + AI 1 + 通知 1 + Flow 2）。

## 测试结果

- vitest **57/57**（新增 5 例）；`npm run build`（含 vue-tsc）✅；eslint ✅；
- 类型坑记录：部分表单的 config 字段是 `unknown`（Flow/Notify），组件 `modelValue` 放宽为 `unknown`、工具函数参数 `unknown` 内部 String 化，单点消化，调用侧零改动；
- NAS 浏览器实测：应用表单编辑「NAS 管理台」→ 下拉正确显示 http://、地址栏只剩主机部分；输入不带协议的地址保存后自动补全（结果见 git 提交）。

## 关键决策

1. **组件替换而非加校验**：用户要的是"少打字"，下拉选择 + 自动识别粘贴比"保存时校验协议格式"体验好；
2. 通知渠道的动态 schema 渲染按 `key === 'url' || 'server'` 条件挂组件，schema 本身不动，其他渠道类型零影响；
3. 探活目标、SSH 主机等 host:port 类输入**有意不套**该组件——它们没有协议语义，套了反而误导。

## 遗留

- 探活方式为 HTTP 时探活目标其实是 URL，但同一输入框在 TCP 方式下是 host:port，混合语义暂不动，后续可按探活类型动态切换控件；
- 登录后回跳原目标页、初始化页加密文案（065/066 遗留）不变。
