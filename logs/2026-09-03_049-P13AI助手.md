# 049 · P13 AI 助手(Provider/流式对话/意图导航/草稿生成)

## 需求原意

连续开发 7 个阶段的第 3 个:**P13 · AI 助手**(M05-1~13,5 步)。不绑死某一家——任何 OpenAI 兼容 API 或本地 Ollama 都能接;除了聊天,重点是"能帮你操作门户"。

## 完成情况

### 13.1 Provider 接入(M05-1~3)
- 配置存设置键 `ai.providers`(JSON 数组,多套),**key 掩码回传、保存时 ****** 保持原值**(与 P9 渠道同构);
- `POST /api/ai/providers/test`(连通性 + 错误摘要)与 `/models`(拉取模型列表供选择);本地 Ollama 填 `http://nas:11434/v1` 即接入。

### 13.2 流式对话(M05-4~9)
- **流式通道定为 WS `/ws/ai-chat`**:P24 加密中间件对 /api 响应全量缓冲,会破坏 SSE;WS 豁免面与 /ws/* 同构(token query 鉴权),帧 delta/done/error——"可随时停止生成"由前端 close 实现;
- 新模型 `ai_conversations`/`ai_messages`(按 user_id 隔离);多会话管理(新建/重命名/删除/历史落库,**首条消息自动截取为会话标题**);
- 上下文轮数 `ai.context_rounds`(0~20,trim_history 只保留最近 N 轮 user/assistant 对);
- 前端 `/ai` 页:会话列表 + 对话流(WS 逐字、**marked Markdown 渲染**(表格/代码块)、流式光标)、快捷指令库(预设 + 一键发送)。

### 13.3 意图导航(M05-10)★
- 系统提示词注入启用的应用清单(id|名称|描述)+ navigate 协议约定;
- `parse_navigate`:识别输出首行 `{"action":"navigate","app_id":N}`,**格式错误/action 不符/非正整数/坏 JSON 一律兜底 None 按普通回答渲染**;
- done 帧带 `navigate_app_id`,前端 toast 后跳转应用页——实测「帮我打开下载器」自动跳转。

### 13.4 上下文与指令(M05-11/12)
- `ai.context_aware` 开关注入 NAS 状态摘要(CPU/内存/磁盘峰值/容器数,复用 P5 采集);快捷指令预设(导航/状态/翻译/总结)。

### 13.5 AI 生成应用草稿(M05-13)
- `POST /api/ai/generate/app-draft`:描述 → 结构化 JSON(名称/描述/探活方式/目标/标签),容忍 ```json 包裹,非法输出 502;前端展示草稿 → **人工确认入库**(实测 Jellyfin 草稿出现在应用列表)。

## 过程中发现并修复

1. **Prompt 模板 JSON 花括号与 `.format()` 冲突**(KeyError '"action"')→ 花括号转义;
2. 会话默认标题不一致(前端「新建对话」vs 后端「新对话」)导致自动改题失效 → 前端传空用后端默认,WS done 后前端刷新会话列表;
3. `receive_json()` 返回 dict,测试里重复 json.loads 报 TypeError。

## 关键决策

1. **流式走 WS 而非 SSE**:P24 加密中间件全量缓冲 /api 响应(逐条确认过 middleware 源码),SSE 必被破坏;WS 明文豁免面已有 /ws/monitor、/ws/notify 先例,架构一致;
2. **Provider 存设置键**而非新表:契约 §3.11 本就有 ai.* 键组,多套配置 JSON 数组足够(单管理员场景);
3. navigate 协议只认输出首行且整行合法 JSON,其余内容一律按 Markdown 回答兜底——杜绝模型"既跳转又解释"时的误跳;
4. Key 全链路不落前端:掩码回传 + WS 帧不含 key(退出标准核验)。
