### 1. 严重缺陷：菜单切换后视图不更新（用户报告 → 当场修复）

**现象**：点击侧边菜单 URL 变化但画面停在原地、时钟冻结、接口请求看似全部消失。
**根因**：P4 新引入的 `vue-draggable-plus` 用法错误——外层区块拖拽同时传了 `target=".section"` 又使用默认插槽，Sortable 初始化拿到 null 根元素，抛出未处理的 `Root element not found / el must be HTMLElement` 异常，**打瘫了 Vue 的响应式调度队列**：整个应用此后不再触发任何重渲染（路由状态在变、视图不动、computed 全部停更）。
**修复**：去掉 `target` 属性回归标准用法；空态提示移出拖拽容器。修复后验证：菜单切换正常、时钟恢复、请求恢复、零控制台错误。
**定位过程**：XHR 打桩 + 启动期错误捕获（临时钩子已移除）发现该未处理 rejection。

## 关键决策

1. 布局模型用「全局扁平 order + sizes + collapsed + sections」JSON，区块内拖拽通过 `reorderSubset` 把局部顺序回填全局位置，跨区块移动（=换分组）暂不支持，走管理页改分组（首页不重复提供）；
2. 收藏是全局标记（api-spec 契约 A 权限），收藏区置顶展示而非双份渲染，避免同一磁贴重复；
3. 磁贴状态点本阶段为灰色占位（`title` 注明 P6 上线后显示），P6 探活数据接入后自动变绿/红；
4. 壁纸图片本阶段支持 URL，本地上传留待后续（icon 上传管线会裁方，不适合壁纸）；
5. 拖拽库实际包名为 `vue-draggable-plus`（dev-plan 原文 `vuedraggable-plus` 为笔误），用法上**不可同时使用 `target` 与默认插槽**（本次事故根源）。
