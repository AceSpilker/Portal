# 111 · 全端口扫描 + 路由器后台式连接设备 + 扫描即识别数据库

## 需求原意

用户四点：①"全设备的全端口扫描，不要只扫描那几个端口"；②路由器 tab 想
要"路由器后台的那些效果"——看到有哪些设备连接这个路由器；③MySQL 还是
没扫描出来（在 3309 非默认端口）；④"查看数据库中的具体内容"还是没做出来。

## 实现

1. **全端口扫描（111-a）**：设备页新增"全端口扫描"按钮（确认框预告耗时
   3~10 分钟）。模式 quick/full：
   - quick：默认端口集（现 28 个，扩充 3307/3308/3309/13306/23306/33060/
     5433/6380/27018/2380/9201/9002/8124 等 alt DB 端口）两阶段扫描；
   - full：先用默认端口+ARP 发现存活主机，再对每台存活主机做 1-65535
     全端口 TCP 扫描（Semaphore 1000 并发、closed 端口 RST 快速失败、
     0.8s 超时、单设备开放端口清单上限 120），进度按主机×端口数推进；
   - 运行记录 kind=devices_full（历史可区分）；进度条区分两种模式文案。
2. **扫描即识别数据库（111-b，同时解决 ③）**：设备扫描完成后对**所有发现
   的开放端口**自动做协议嗅探（MySQL greeting → Redis PING → PG SSLRequest
   → HTTP 族），命中即 upsert 进数据库服务清单——MySQL 无论开在哪个端口，
   扫一次就会被自动发现并显示版本，无需任何配置。quick 模式默认端口集已含
   3309 等 alt 端口，同样生效。
3. **路由器后台式连接设备（111-c）**：/api/lan/router/clients 三源融合——
   设备清单（主机名/类型/在线，最全）+ 本机 ARP + 路由器 SNMP；表格新增
   在线状态胶囊/主机名/类型列，在线置顶+统计 chips；附提示：路由器开启
   SNMP 并配置 community 后即可读到路由器自身的连接设备表（与后台一致）。
4. **数据浏览引导（111-d，同时回应 ④）**：查看器抽屉顶部按凭据状态显示
   banner——未配置凭据（红）/上次测试失败（黄）+ "去配置凭据"按钮（打开
   凭据对话框并预填该服务的 host:port:类型）。数据浏览功能本身（库→表→
   数据分页）110 已实现；用户此前看不到，正是因为 MySQL 未被发现 + 凭据
   未配对——①③解决后链路即通：扫描发现 MySQL → 配正确密码 → 浏览数据。

## 测试结果

- 后端 ruff 全绿；pytest **288 passed**（新增：full 模式 kind 持久化、
  clients 三源融合结构；修正三个用例的 _run_scan fake 签名级联）；
- 前端四关全绿；
- NAS 部署后实测见补记。

## 遗留

- 全端口扫描耗时与网络规模正相关（254 主机 × 存活台数），UI 已预告；
  后续可选：按设备粒度的"仅此设备全端口扫描"入口。
