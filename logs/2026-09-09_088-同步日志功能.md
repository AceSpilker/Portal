# 088 · MySQL 同步与 Redis 缓存：同步日志功能

## 需求原意

用户要求给「MySQL 同步」和「Redis 缓存」各加一个同步日志功能——记录每次同步/连接事件的历史。

## 现状说明

两模块此前只有"当前状态"没有"历史"：MySQL 有 sync_state（每表最后一次推送的结果，会被覆盖），
Redis 只有实时 mode/last_error（降级恢复一条日志都不留）——出了问题无法回溯"什么时候开始失败、
失败过几次"。

## 完成情况

### 1. 数据模型与服务（共用一张表）

- `sync_logs` 表（models/sync.py）：`kind`（mysql/redis）/ `action`（push/restore/test/
  connect/degrade/recover/disable）/ `status`（ok/failed/info）/ `duration_ms` / `message`；
- `services/sync_log.py`：独立 Session 写入 + **每 kind 保留最近 200 条**（写入后裁剪），
  失败静默绝不影响业务；`fire()` 供事件现场 asyncio task 旁路触发；
- 查询端点 `GET /api/sync-logs?kind=&limit=`（管理员）。

### 2. MySQL 埋点

- `push_all` 三个出口全部记录：未启用（info）/ 连接失败（failed + 错误）/ 部分表失败（failed +
  失败明细）/ 成功（ok + 行数表数 + 耗时）；**退避跳过不记**（避免调度轮询刷屏）；
- `/mysql/test` 连接测试、`/sync/restore` 灾难恢复各记 test/restore 事件（含耗时）。

### 3. Redis 埋点

- `configure_redis` 连接成功/失败（**仅状态变化时记录**：健康检查 30s 重试不再刷屏——
  实测修复前 30s 一条 connect/failed，修复后 40s 两周期零新增）；
- `ping()` 健康检查的降级（degrade/failed）与回切（recover/ok）——只在模式翻转时记；
- `/redis/test` 测试、面板停用 Redis（disable/info）。

### 4. 前端

- 新共用组件 `SyncLogList.vue`（kind prop）：最近 30 条，时间/动作/状态 tag/耗时/消息 + 刷新；
  MySQL 同步与 Redis 缓存面板底部各接一份；
- `syncApi.syncLogs(kind)`；i18n 双语 6 键。

## 测试结果

- 后端：全量 **247 passed / 2 skipped**（新增 test_z_sync_logs 3 例：push 记录、Redis 测试失败
  捕获、kind 筛选与字段形状），ruff ✅；
- 前端：vitest 57/57 ✅、eslint ✅、build（vue-tsc）✅；
- 本地浏览器实测：MySQL 面板「立即推送」→ 同步日志出现 push/info「同步未启用，跳过推送」✅；
  Redis 面板「测试连接」→ connect/failed 与 test/failed 带完整错误消息 ✅；健康检查重试
  40s 两周期零新增（刷屏抑制生效）✅。

## 关键决策

1. 两模块共用一张表（kind 区分）而非各建一张：结构相同、端点/组件/清理逻辑全部复用；
2. Redis 连接日志只在状态变化时记录：健康检查周期性重试会把 200 条保留窗刷满，
   只记"首次失败/失败转成功"才保留可回溯的历史；
3. MySQL 退避跳过不记：跳过是常态路径（按间隔调度），记了全是噪音。

## 遗留

- Redis 启用但断连期间的 30s 探活重试成功回切只记一条 recover（符合预期）；
- 日志条目无分页（limit≤200 上限 = 保留窗上限），后续需要再加。
