# 078 · 端口总览协议补全：UDP 监听端口缺失修复

## 需求原意

用户发现端口总览数量不对，怀疑协议不全。

## 根因（两类，都修了）

1. **psutil 路径（Linux/NAS root）**：过滤条件只收 `psutil.CONN_LISTEN`，而 **UDP 套接字没有 LISTEN 状态**（绑定即服务，状态恒为 CONN_NONE）——UDP 全部被漏掉；
2. **lsof 回退路径（macOS 非 root）**：`lsof -nP -i` 解析只认 `node == "TCP"` 行，UDP 行同样被丢弃。

两条路径殊途同归：UDP 服务端口全部缺失。这正是用户"端口条数不对"的直接原因（本机 UDP 服务 rapportd:3722、Chrome mDNS:5353 全部不可见）。

## 完成情况

| 修复 | 内容 |
|---|---|
| psutil 分支 | UDP：`status == CONN_NONE` 且已绑定本地地址即收录；TCP 仍只取 LISTEN |
| lsof 回退分支 | 命令加 `-sTCP:LISTEN`（TCP 只留监听）；解析器接受 TCP/UDP 行，proto 取 node 小写 |
| 去重 | (proto, addr, port, pid) 四元组去重（IPv4 映射/SO_REUSEPORT 重复行） |
| UDP 动态端口段过滤 | 出站客户端套接字（DNS/WebRTC 等）绑定在 IANA 动态段 49152-65535，不是服务，公共出口统一剔除——否则 macOS 本机实测混入 140+ 条 Chrome 临时套接字噪音 |

## 测试结果

- 本机（macOS，lsof 路径）：total 21 = TCP 19 + UDP 2（rapportd:3722、Chrome mDNS:5353），噪音剔除生效；
- 后端全量 **232 passed / 2 skipped** ✅、ruff ✅（含超长注释行修正）；
- 浏览器实测：端口总览统计徽标与 UDP 行渲染正常，此前一键加入的监控项"监控中"标签正常。

## 关键决策

1. **UDP 动态端口段剔除而非全收**：全收会混入上百条出站客户端套接字（Chrome 一家就 140+ 条），失去"服务端口"语义；剔除段为 IANA 标准动态段，服务极少绑定该段；
2. 探活按钮只对 TCP 行展示（UDP 无法用 TCP connect 探活，避免建成永远"异常"的监控项）。

## 遗留

- Linux 临时端口段 32768-60999 与 IANA 段部分重叠（32768-49151 的出站套接字仍可能漏进列表）——部署端为 root+容器 HOST_PROC 场景，如噪音明显再按平台细分；
- UDP 行不提供"加入监控"（探活仅支持 TCP connect/HTTP），前端已按协议隐藏按钮。
