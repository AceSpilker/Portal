### 缺陷修复：P24 遗留——认证 GET 全部 1100 失败（重要）

- **现象**：浏览器端到端验证时，`GET /api/categories`、`GET /api/apps` 等一律 400（1100 secure session required）；
- **根因**：axios 请求拦截器只在**有请求体**时附带 `X-Session-Id`，而无 body 的请求（认证 GET、`/auth/refresh`）虽加密了 Authorization 头却没带会话 id，中间件无法解密。P1 首页无认证 GET，故此前未暴露；静默续期同样受此影响（token 过期会被迫登出而非续期）；
- **修复**：`secure.ts` 导出 `currentSessionId()`，`request.ts` 在每个非豁免请求上统一附带 `X-Session-Id`（frontend/src/api/request.ts:46）。

## 关键决策

1. **图标上传走 base64 JSON 而非 multipart**：P24 要求 /api 全部密文，multipart 无法走加密信封；故 `upload-icon` 接收 `{filename, data(base64)}`，api-spec §4.2 已同步口径（HTML 双版本已改）；
2. **favicon 抓取兜底链**：站点 favicon.ico → 页面 link 解析（apple-touch 优先）→ Google s2；全失败返回 4004 业务失败，不炸接口；测试用 httpx MockTransport 注入，不发真实网络请求；
3. **导入为覆盖式且保留 id**：满足"清库导入后数据一致"的验收口径，同时为 P23 MySQL 镜像推送的 upsert 语义打样；
4. **测试文件命名 `test_p2_apps.py`**：字母序置于既有文件之后执行，用 sqlite3 直连重置 admin 密码，与前置用例的改密链路解耦，可独立运行也可全家桶运行。
