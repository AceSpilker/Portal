# 070 · 设置·外观面板空白修复（vue-i18n 消息编译地雷）

## 需求原意

用户反馈：设置中的"外观"现在是空白画面。

## 根因

`settings.customCssPh`（自定义 CSS 输入框的占位文案）的值是一段 CSS 示例：`.tile-name { font-weight: 700; }`。vue-i18n 把 `{...}` 视为**变量插值语法**，渲染外观面板调用 `t('settings.customCssPh')` 时消息编译器对 ` font-weight: 700; ` 抛 `SyntaxError`，Vue 中止该组件渲染，面板位置只剩空注释节点 `<!---->`——即用户看到的空白。

该雷自 P17.2（自定义 CSS 功能）上线即存在：vue-i18n 消息**懒编译**，只有点开"外观"标签才会编译该 key，其余页面不受影响，因此长期未被发现。本次用户首次点开外观即命中。

## 排查路径（备查）

1. 浏览器复现：点外观后菜单高亮但内容区仅剩占位段落，面板 DOM 为 `<!---->`；
2. window.onerror 无捕获（Vue 渲染异常走 console.error），补捕 console.error 得 `SyntaxError: 2`；
3. 堆栈 `nextToken/parse` 定位为 @intlify 消息编译器；
4. 用 `@intlify/message-compiler` 本地逐条编译两个语言包全部消息，唯一炸点即 `customCssPh` 的 CSS 花括号。

## 完成情况

**已修复并部署。** 用 vue-i18n 字面量转义语法改写占位文案（渲染结果不变）：

```
'.tile-name { font-weight: 700; }'          → 修复前（编译炸）
'.tile-name {'{'} font-weight: 700; {'}'}'  → 修复后（{'{'} 输出字面 {）
```

zh-CN 与 en 两个语言包同步修改；`@intlify/message-compiler` 本地编译验证通过。

## 测试结果

- vitest 57/57、build（vue-tsc）✅、eslint ✅；
- NAS 重建后浏览器实测：外观面板完整渲染——暗色模式（跟随系统/亮色/暗色）、主题色 8 预设 + 取色器、壁纸类型与自定义 CSS 输入框（占位符显示正常），无控制台报错。

## 关键决策

1. **修文案而非绕过**：用 vue-i18n 官方字面量转义，占位符显示内容与原来完全一致；
2. **全量扫描**：对两个语言包全部消息做了 `{...}` 插值合法性扫描（合法=标识符），确认仅此一处地雷，其余 `{version}`/`{n}`/`{name}`/`{code}` 均为合法插值；
3. 渲染异常走 console.error 而非 window.onerror——排查 Vue"空白组件"问题时需捕获 console.error，记入排查经验。
