# 110 · 局域网发现四项修复：网段识别/凭据弹窗/非默认端口 MySQL/数据浏览

## 需求原意

用户反馈四个问题：①NAS 上扫描"还是不对"（仍然只看容器网络）；②数据库服务
tab 中凭据管理弹出画面显示不对；③检测出了 minio 和 redis，但还有一个 MySQL
没扫出来——**端口不是默认的**；④核心诉求：登录进服务后能看到里面有什么，
"mysql 的时候可以通过登录，看有哪些库哪些表哪些数据"。

## 诊断（部署形态实测）

- **NAS 上 `lan.scan_cidrs` 被存成了 `127.0.0.0/8`（回环，无效配置）**，且
  `lan.probe_ports` 只剩 `[80,445,22,443]`——排查发现 `PUT /lan/settings`
  旧实现是全键覆盖：body 里没带的键一律按空值落库（探测端口 11 个被清成空
  → 运行时只剩 4 个兜底端口）。用户此前的扫描实际只扫了 `192.168.5.1/32`
  单个地址（历史扫描记录为证）。
- 用户 MySQL 实际在 **192.168.5.88:3309**（端口扫描确认，greeting 读出
  **8.0.45**）——固定端口字典（3306/6379/9000…）自然扫不到。

## 修复与新增

1. **网段识别（110-a）**：
   - `lan_scan.sanitize_cidrs`：读/存配置统一清洗（丢弃回环/公网/超 4096
     地址/垃圾条目），坏配置不再阻塞，自动落到下一优先级；
   - `PUT /lan/settings` 改为**只更新 body 中实际出现的键**（修全键覆盖 bug）；
   - 新增 `LAN_SCAN_CIDRS` 环境变量（docker-compose 已为 NAS 设
     `192.168.5.0/24`），优先级：设置（清洗后）→ env → Portal 访问地址派生
     → 容器网关 /24；
   - 新增 `stored_hint_ips`：从已发现服务/应用 LAN 入口收集局域网 IP 作提示
     兜底；
   - NAS 库里的坏数据已直接修复（scan_cidrs 清空、probe_ports 恢复全量）。
2. **非默认端口 MySQL（110-b）**：
   - `sniff_unknown` 通用协议嗅探：MySQL greeting（服务端先发）→ Redis
     PING → PG SSLRequest → HTTP 族（MinIO/ES/etcd/ClickHouse）；
   - `lan.db_extra_ports` 设置（扫描设置里可填"如 3309, 13306"），DB 扫描
     目标 = 固定字典 + 额外端口（嗅探模式）；
   - **手动添加服务**：DB 页签新增"添加服务"（POST /api/lan/db/services），
     填 host:port 立即嗅探识别；识别失败也入库（down），可先配凭据，服务
     可达后定时探活接续。
3. **MySQL 库→表→数据浏览（110-c，用户核心诉求）**：
   - `GET /api/lan/db/mysql/{sid}/rows?schema=&table=&page=`：固定 SELECT
     模板 + 标识符白名单（`^[A-Za-z0-9_$]+$` ≤64 字符 + 反引号引用）杜绝
     注入；COUNT 总数分页；单元格截断 200 字符、bytes → `<binary N> hex`
     摘要、NULL 斜体显示；
   - MysqlViewer 库表页签：点库名快捷过滤、每表"数据"按钮打开分页数据对话框。
4. **凭据弹窗重构（110-d）**：凭据管理从"抽屉内嵌套对话框"（Element Plus
   层叠/遮挡问题根源）改为**单层 760px 对话框内列表/表单双视图**，与其他
   页面的弹窗范式一致。

## 测试结果

- 后端 ruff 全绿；pytest **287 passed**（新增：标识符白名单注入用例、
  sanitize_cidrs 清洗用例；修正 test_08 fake 签名）；
- 前端四关全绿（vitest 57/57、eslint、vue-tsc+build）；
- **真机链路**（本地 dev + 家庭网段）：
  - `sniff_unknown('192.168.5.88', 3309)` → `{mysql, 8.0.45}` ✅；
  - UI 手动添加 192.168.5.88:3309 → "已添加并识别：mysql 8.0.45"，清单出现
    "通 mysql …8.0.45 已配置 查看" ✅；
  - 凭据表单（root/空密码）保存 → 测试连接返回清晰错误摘要 `(1045, "Access
    denied for 'root'@'172.17.0.1' (using password: NO)")`——连接链路与错误
    路径 ✅（正确密码由用户填入后即可浏览数据）；
  - 凭据管理/新建凭据弹窗截图确认显示正常 ✅。
- NAS 部署后容器内验证见下方补记。

## 遗留

- MySQL 正确密码由用户在凭据管理中填入（当前 NAS 库里留有我测试用的
  root/空密码凭据且标记 FAIL，用户编辑填对密码即可）；**线上 NAS 库未做
  此测试**（NAS 库无该凭据），部署后用户首次使用时走相同流程；
- 设备扫描默认 probe_ports 未包含 3309 等 alt 端口——用户可在扫描设置
  自行补充；DB 扫描用 db_extra_ports 覆盖此场景。
