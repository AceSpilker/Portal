4. **P5.4 历史查询**：`GET /api/monitor/history?metric=&range=`——24h 原始分钟粒度、7d/30d 按 20min/1h 桶平均；cpu/mem/net 输出 points、disk 按挂载点分组。

**网卡速率的两个正确性要点**：① 速率由相邻快照差值计算，「当日流量」用跨日基线（昨日末帧为今日基准，计数回绕钳 0，中途新出现网卡首见登记基线）；② 间隔 <1s 的快照不重算速率（HTTP 概览与 WS 两路推送交替触发时沿用上一窗口值），避免除以极小间隔产生速率尖峰——回归时实际观测到该风险并加了防御 + 单测锁定。

## 关键决策

1. ECharts 按需注册（core+Line+Grid/Legend/Tooltip+Canvas）控制包体；首页速览用纯 SVG 环形图避免首页引入图表库；
2. WS 鉴权走 query token（WS 不适用 Authorization 头信封），与加密豁免面（静态资源）同级；
3. 聚合/清理测试用独立内存库跑，规避与 TestClient lifespan 启动的采样定时器及跨事件循环连接复用的干扰。

## 发现并处理的问题

- uvicorn `--reload` 在「新代码引用未安装依赖」窗口期会导入失败并停留在旧代码，恢复依赖安装后未自动拉起——重启后端进程解决。开发时依赖安装与代码引用顺序需注意（Windows/热重载环境现象，非代码缺陷）。

## 回归修复（用户反馈：历史曲线 tab 切换显示不对）

四个叠加缺陷，已全部修复：

1. **ECharts option 合并残留（主因）**：`MonitorChart` 的 `setOption` 用默认 merge 模式，指标切换后 series 数量不同（网络 2 条 vs CPU/内存 1 条），旧序列（如「上行」）残留并与新序列混画、图例错乱。改为 `notMerge: true` 整体替换；
2. **disk 指标 x 轴为空**：前端 labels 取自 `points`，而 disk 响应只有 `mounts` → 数据比坐标轴长而错位。改从 `mounts[0]` 取时间轴；
3. **后端 disk 多挂载点时间轴不对齐**：原按各挂载点首行时间分桶，出现晚的盘点数不同。改为全挂载点共享统一时间轴（24h=全部行时刻去重；桶模式=全局 origin 划桶、桶 ts 取桶尾），缺失时刻补 `null`，前端 `connectNulls: false` 留断口；
4. **切换瞬间旧响应被新指标字段读取**：切换即清空 `history` 再拉取，避免短暂错图。

测试：新增 disk 多挂载点对齐断言（等长/缺失 null/ts 一致，24h 与桶模式各一），全量 **102 passed**、ruff/ESLint/tsc 干净，浏览器截图确认切换后图例与序列干净。
