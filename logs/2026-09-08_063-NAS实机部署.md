# 063 · NAS 实机部署（192.168.5.88，Docker 单容器）

## 需求原意

用户要求把项目部署到局域网 NAS（192.168.5.88）的 Docker 中，缺什么向用户要。

## 完成情况

**部署成功，服务已在 NAS 上常驻运行。**

| 项 | 值 |
|---|---|
| 目标机 | 群晖 DSM 7.2.2，x86_64，Container Manager（Docker 24.0.2 / Compose v2.20.1） |
| 部署路径 | `/volume1/docker/portal`（tar over ssh 同步源码，排除 .git/node_modules/.venv/data/logs） |
| 启动方式 | `docker compose up -d --build`（仓库 Dockerfile + docker-compose.yml） |
| 对外地址 | `http://192.168.5.88:8080`（NAS 8080 → 容器 8000） |
| 数据持久化 | `/volume1/docker/portal/data` → 容器 `/app/data` |
| 配置注入 | `docker-compose.override.yml`（NAS 侧手工创建，不进仓库）：随机 `SECRET_KEY`（openssl rand -hex 32）+ `HOST_PROC=/host/proc` + `HOST_SYS=/host/sys`（监控读宿主机资源，只读挂载 /proc、/sys） |

## 验证结果

- `docker ps`：portal **Up (healthy)**（compose 自带 /api/health 探活通过）；
- `GET /api/health` 200：`{"status":"ok","initialized":false}`——全新实例，首次访问 Web 会引导创建管理员账号；
- Web 首页 200，NAS 本机与局域网（Mac）均可达，响应 7ms；
- 与 NAS 上已有 13 个容器（mysql、portainer、nginx 等）并存，端口无冲突。

## 关键决策

1. **pip 源清华 → 中科大**：清华源 `pypi.tuna.tsinghua.edu.cn` 在该 NAS 容器内被 DNS 解析为纯 IPv6（2402:f000::/32）且容器无 IPv6 出口，pip 报 `from versions: none`。实测中科大/腾讯/豆瓣三源双栈可达，Dockerfile 固定用中科大并注释原因（本仓库唯一代码改动）。
2. **NAS 上构建而非本地构建传输镜像**：NAS 有原生 compose build 能力，避免本机 arm64 镜像跨架构问题；npmmirror + 中科大源保证国内拉取速度。
3. **rsync 不可用改 tar over ssh**：macOS 新系统 rsync 实为 openrsync，与群晖 GNU rsync 3.1.2 协议握手失败（`Permission denied` + EOF）。
4. **SSH 免密**：用户账号家目录原为 777，sshd StrictModes 拒绝公钥，收紧为 755 后写入 `authorized_keys`；后续运维走 `ssh nas-portal`（~/.ssh/config 别名，端口 8082）。
5. **不动 daemon 配置**：曾评估配 registry 镜像加速，但需重启 dockerd 会波及 NAS 上其他在跑容器，改用逐层等待自然完成。

## 遗留 / 下一步

- **首次初始化**：浏览器打开 http://192.168.5.88:8080 创建管理员账号（`initialized:false` 待初始化）——属用户操作，未代劳；
- **P3/P8/P23/P25 实机验收**：README 声明的 NAS 实机项（真实环境验收、72h 长稳）现具备执行条件，待用户发起；
- **可选能力未开启**：`DOCKER_SOCK_ENABLED`（容器管理，有安全权衡）、MySQL 镜像推送，均为默认关闭，用户需要时改 override 即可；
- **SSH 安全**：部署用 SSH（8082）仍开启，公钥已授权；用户如介意可在 DSM 关闭或改回密码登录；
- 升级流程：本机 push 后在 NAS `cd /volume1/docker/portal && tar 同步覆盖 && docker compose up -d --build`，data 卷不丢数据。
