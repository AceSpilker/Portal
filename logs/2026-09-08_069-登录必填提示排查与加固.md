# 069 · 登录"用户名或密码必填"排查与两端加固

## 需求原意

用户反馈登录时提示"用户名或密码必填"。

## 排查结论

登录服务端三态实测全部正常：错误密码 → `1001 用户名或密码错误`；空请求体 → `2001 参数校验失败：用户名/密码 为必填项`；正确凭据 → 签发 token。浏览器端正常填表登录请求体完整、一次成功。**用户所见为服务端 2001（到达后端的请求体里没有用户名/密码），正常填表无法复现**。两类可能成因都做了加固：

1. **密码管理器"幽灵回填"**（最可能）：浏览器回填保存的凭据时不触发 input 事件，输入框看得见字但 Vue v-model 仍为空——部分浏览器行为下客户端校验先拦（"请输入用户名和密码"），个别路径（回填时机/自动提交）到达服务端即为空体。
2. **安全上下文 × 加密关闭错配**（隐患级）：HTTPS 访问时 `crypto.subtle` 可用，前端会握手并加密请求体；若服务端 `ENCRYPT_ENABLED=false`（本部署形态），中间件旁路、后端按裸 JSON 读信封 → 必然 2001"必填"。当前 8080 为纯 HTTP 不会触发，但未来 DSM 反代 HTTPS 时必踩。

## 加固内容

1. **前端 `LoginView`**：提交时若 v-model 为空，按 id（`login-username`/`login-password`）从输入框回读兜底，密码管理器回填值不再丢失；
2. **后端 `/api/crypto/public-key`**：`encrypt_enabled=false` 时显式返回 `{"enabled": false}`（此前无论开关都发公钥）；
3. **前端 `secure.ts`**：握手前识别 `enabled:false` → 进入"服务端驱动的明文模式"（`isPlaintextTransport` 同时覆盖 HTTP 非安全上下文与服务端关闭两种来源），不握手、不加密请求体/响应体。

## 测试结果

- 后端：定向 27/27（auth→crypto→spa）+ 全量 **223 passed / 2 skipped**；ruff ✅；
- 前端：vitest 57/57、build（vue-tsc）✅、eslint ✅；
- NAS 重建后回归验证（见下）。

## 关键决策

1. 握手接口返回 `enabled` 标志而非让前端猜测：状态由服务端权威下发，未来切回 HTTPS + 开加密时前端自动恢复加密会话，零配置联动；
2. 登录表单 DOM 回读仅作为 v-model 为空时的兜底，正常输入路径行为不变；
3. 教训：`test_crypto` 依赖 `test_auth` 先执行（文件名字母序），定向单跑会假失败——已按依赖顺序验证，测试间顺序依赖记入 065 的 flaky 清单。

## 遗留

- 若用户再次遇到"必填"提示，请提供：浏览器及访问地址（是否 localhost/HTTPS/带端口）、是否用了密码管理器回填——用于进一步定位；
- 065/066/067/068 遗留项不变。
