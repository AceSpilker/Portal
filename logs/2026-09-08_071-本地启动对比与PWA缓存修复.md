# 071 · 本地启动对比验证 + PWA 入口文件缓存策略修复

## 需求原意

用户反馈服务器上外观菜单仍无内容，要求把项目在本地启动起来对比验证（此前均跑在服务器上）。

## 排查结论

1. **本地启动验证通过**：后端（临时 DATA_DIR 全新库 + 加密默认开启）8000 + 前端 vite dev 5173，localhost 为安全上下文走**完整加密握手链路**，初始化 → 登录 → 设置 → 外观面板四区块（暗色模式/主题色/壁纸/自定义 CSS）完整渲染；
2. **服务器与本地 bundle 哈希一致**（`index-i7yMRAEI.js`），此前新开标签实测外观也正常——**服务器内容是修复后的**；
3. 用户仍看到空白的真因：项目是 **PWA（vite-plugin-pwa，sw.js 预缓存 + autoUpdate）**，浏览器里旧 Service Worker 会继续供给旧资源，autoUpdate 机制下需要**连续两次刷新**（旧 SW 让位 → 新 SW 接管）才能看到新版本，刷新一次看到"还是旧样子"符合机制。

## 加固：入口文件禁缓存

此前 StaticFiles 无显式 Cache-Control，浏览器对 index.html/sw.js/registerSW.js/manifest.webmanifest 走启发式缓存，SW 更新检查可能长时间拿不到新 sw.js，发版生效依赖运气。已在 `_SpaStaticFiles` 中对**入口类文件**（index.html、sw.js、registerSW.js、manifest.webmanifest、workbox-*.js、根路径）加 `Cache-Control: no-cache`；带哈希的 `/assets/*` 保持默认（内容寻址，永久缓存语义正确）。

坑记录：StaticFiles 对 `/` 请求传入的 path 是 `"."`（当前目录），根路径判断必须把 `.` 归一化，否则根页面永远漏标。

## 测试结果

- 后端定向 5/5（static_spa + health）、ruff ✅（首轮 E501 超长行已修）；
- 前端 vitest 57/57（本地 dev 验证不依赖它，属正常关卡）；
- NAS 重建后实测响应头：`/`、`/sw.js`、`/login`（SPA 回退）均 `cache-control: no-cache`；`/assets/index-*.js` 无该头（正确）；
- 本地加密链路：localhost 安全上下文 → WebCrypto 握手 → 登录/外观全流程 ✅（070 的明文模式与本次加密模式双态均验证）。

## 遗留 / 给用户的操作指引

- **立即看到服务器新版**：在出现旧画面的浏览器上硬刷新（macOS `Cmd+Shift+R`）一到两次，或 浏览器设置 → 清除站点数据（仅 192.168.5.88:8080）；
- 本次部署后 SW/index 已带 no-cache，**此后每次发版刷新一次即生效**；
- 本地开发环境仍在运行：前端 http://localhost:5173（临时库管理员 localadmin / Local@2026），不需要时 `pkill -f uvicorn` + `pkill -f vite` 即可关闭；
- 可选增强（未做）：前端接 `registerSW({ onNeedRefresh })` 弹"发现新版本，点击刷新"提示，体验更佳。
