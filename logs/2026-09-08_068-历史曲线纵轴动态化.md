# 068 · 监控历史曲线纵轴动态化（速率/温度不再钉 100）

## 需求原意

监控页「历史曲线」模块中，网络流量与 I/O 两种指标的纵轴最大值太小（钉在 100 KB/s），应参考上方独立卡片按数据动态调整；温度同样不能限制最大 100，应动态。

## 根因

ECharts value 轴默认"取整"缩放会把 40~99 区间的数据最大值都圆整到 100 上限——NAS 日常流量峰值 ~48 KB/s、温度 ~54°C，纵轴一律被画到 0-100，曲线被压到半格以下，视觉失真。历史曲线与独立卡片（netOption/ioOption 原本无 max）都受同一行为影响。

## 完成情况

**已实现并部署。**

`MonitorView.vue` 新增动态轴工具：

- `dynamicMax(pad, step, floor)`：按数据最大值 × 余量系数后按步进取整的 yAxis.max 回调；
- `rateYAxis`：速率轴（存储单位 KB/s）——上限 = max×1.15 按 8KB/s 步进取整（下限 8），**刻度标签直接用 formatRate 格式化为可读速率**（如 "5.4 MB/s"、"2.0 KB/s"），与悬停提示一致，替代原先裸 KB 数字 + "KB/s" 轴名；
- `tempAxisMax`：温度轴——上限 = max×1.1 按 5°C 步进取整（下限 20°C），数据高时自然抬高（87°C → 100 是数据驱动，45°C → 50），不再无差别钉 100。

应用位置（6 处）：

| 图表 | 处理 |
|---|---|
| 独立卡片·网络流量 | rateYAxis |
| 独立卡片·I/O | rateYAxis |
| 历史曲线·网络流量 | rateYAxis |
| 历史曲线·I/O | rateYAxis |
| 历史曲线·温度 | tempAxisMax（磁盘/GPU 保持 0-100 百分比语义不变） |
| 历史曲线·CPU/内存 | 不变（百分比钉 0-100 是正确语义） |

## 测试结果

- vitest 57/57、build（vue-tsc）✅、eslint ✅；
- NAS 重建后截图实测（全部通过）：
  - 历史曲线·网络流量：纵轴 0~50 KB/s（数据峰值 ~48），刻度 "10.0 KB/s…50.0 KB/s" 可读格式，曲线占满绘图区；
  - 历史曲线·温度：纵轴 0~70°C（数据峰值 ~62），5 路传感器完整渲染，不再钉 100；
  - 独立卡片·网络流量/I/O：0~8 KB/s / 0~1000 KB/s 动态可读刻度；
  - CPU/内存：保持 0-100 百分比（正确语义不变）。

### 附加修复：图表切换残留

首轮验证发现历史曲线切到"网络流量"后左上角残留"%"轴名——`MonitorChart` 此前 merge 更新只 replaceMerge series，旧轴的 name/formatter/max 会残留到新指标。已把 xAxis/yAxis 纳入 replaceMerge（坐标轴每次整体重声明，替换合并无残留），并为各轴显式补全 name 与刻度 formatter（防止跨指标合并污染）。

## 关键决策

1. **上限回调而非 scale:true**：ECharts `scale:true` 只影响非零基线，解决不了取整钉 100；显式 max 回调一步到位且步进取整保证刻度整洁；
2. **速率刻度直接带单位**：去掉 "KB/s" 轴名，刻度格式化成 formatRate 人类可读串，与卡片头部 "↓ 6.0 KB/s" 的表达一致；
3. 磁盘/GPU/内存/CPU 百分比语义**有意保留** 0-100 钉死——百分比量纲固定才是对的，不搞一刀切动态化。

## 遗留

- 历史曲线采样粒度（1440 点 lttb）在极小流量下仍会显得平缓，属采样语义非缺陷；
- 065/066/067 遗留项不变。
