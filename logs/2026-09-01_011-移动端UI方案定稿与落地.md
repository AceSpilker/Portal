## 需求（用户原意）

系统在移动端访问时也需要 UI 适配，看一下采用什么方案，整体架构设计里也要把移动端 UI 方案加进去。

## 方案决策：响应式 + 移动端布局适配（方案 A）

| 候选方案 | 结论 |
|---|---|
| **A. 响应式 + 移动端布局适配（一套代码库）** | ✅ **采用**：断点样式 + 底部 Tab + 组件条件渲染；门户以卡片为主，天然适合自适应 |
| B. 独立移动端 H5（Vant 等） | ✗ 双代码库/双份维护，个人项目成本翻倍 |
| C. 跨端 App（uni-app/Flutter） | ✗ 远期按需评估（需要推送/扫码等原生能力时） |
| D. 桌面页面直接缩放 | ✗ 否决 |

## 完成情况

### 1. 代码落地（frontend）

- 新增 `composables/useIsMobile.ts`：基于 @vueuse useMediaQuery 的全局共享断点状态（`<768px` 移动 / 768~1079 平板 / ≥1080 桌面）；
- **仪表盘外壳移动适配**：桌面侧边栏在移动端隐藏，改为**底部 Tab 导航**（首页/应用/监控/Flow/AI，≤5 项、图标+文案、:active 缩放反馈）；主区底部预留 Tab 高度 + `env(safe-area-inset-bottom)`；欢迎横幅移动端纵向堆叠；卡片网格移动端双列（≤400px 单列）；
- **登录页移动适配**：卡片内边距收紧、品牌字号缩小、页面留白含安全区；
- 触控规范：可点击目标 ≥44px。
