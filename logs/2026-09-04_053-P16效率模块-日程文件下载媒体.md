# 053 · P16 效率模块：日程提醒 / 文件管理 / 下载媒体

## 需求原意

连续开发第 6 个阶段：**P16 · 效率模块**（3 步，M2）——16.1 日程与提醒（M13-1~5：月视图日历/待办/提醒推送/重复规则/农历节日生日）、16.2 文件管理基础（M11-1~4/6：白名单目录/上传下载/文件操作/媒体预览/图标归档联动）、16.3 下载与媒体（M12-1/2/4/5：qBittorrent 集成/添加任务/完成通知/Jellyfin 海报墙）。定位为"每天会打开的效率入口"，轻量只读联动、不做重型网盘/全套下载客户端。

## 已完成

### 后端（177 例全绿，新增 10 例）
- **农历服务** `services/lunar.py`：通行 1900-2100 数据表，solar↔lunar 互转（闰月排在常规月后）、九大农历节日+除夕推算；锚点校验（2026 春节 02-17/中秋 09-25/端午 06-19、2025 闰六月、1980/2025 春节）+ **2025 全年 365 天 round-trip**；
- **日程** `api/v1/schedule.py`：calendar_events/todos 模型（user_id 隔离）；`GET /calendar/month` 按重复规则（daily/weekly/monthly/yearly/custom 间隔）展开 + 当月节日；CRUD 全套；`reminder_scan` 每 30s 扫描到期事件 → P9 `notify.dispatch`（event=schedule.reminder），`last_remind_key` 按 occurrence 去重，错过 12h 窗口丢弃；
- **文件** `api/v1/files.py`：files.roots 白名单（空=404 前端隐藏）；realpath 防穿越（含 symlink）；list/upload/download/mkdir/rename/delete/move；上传下载走 JSON+base64（≤100MB/64MB，保持 P24 全链路密文）；`POST /files/raw-url` 签发 10 分钟 JWT → `GET /files/raw?token=`（/api 之外，随静态资源豁免信封，TLS 为基线；服务侧二次校验白名单）；`core/security.py` 新增通用 `create_signed_token`；
- **下载媒体** `services/qbittorrent.py` + `api/v1/downloads.py`：qB v2 API 客户端（login SID cookie/torrents info/add，支持 MockTransport 注入）；summary/tasks/add 端点（未启用 404）；`downloads_job` 60s 轮询完成跳变 → 通知（event=downloads.complete）；Jellyfin `Items/Latest` ≤12 项，海报服务端代理转 data URI（api_key 不落前端）；
- 设置键（全部入 settings 白名单校验）：files.roots/downloads.*/media.*；调度注册 schedule_reminder(30s)/downloads_poll(60s)。

## 过程中发现并修复

1. **lunar_to_solar 两处逻辑错误**：初版未逐月推进（直接拿 day 对第一个月判断）；修正后又把闰月排在常规月前（正确历法：闰 N 月在 N 月之后）——最终以 2025 全年 round-trip（含闰六月）兜底验证，除夕改为"当年春节前一天"；
2. POST /api/me/tabs 的教训复用：新接口的必填/可选语义先对齐再写（本次 files.roots 直接进了 settings 白名单与校验器）；
3. ruff E501 按 CJK 双宽计算行宽——i18n 折行脚本改用 east_asian_width 度量；
4. p15 测试一处 `for l in ...` 触发 E741（上会话遗留），顺带清理。
