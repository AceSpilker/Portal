# 085 · 天气城市可配置（来源说明 + 设置 UI + 预览）

## 需求原意

用户问首页天气从哪来、地理位置怎么定的，并要求"可以设置获取哪个地方的天气信息"。

## 现状说明（回答用户疑问）

- **数据来源**：`wttr.in` 公共免费天气服务（无需 API key）。后端 `/api/widgets/weather` 代理请求
  （4s 超时），失败返回 null、前端组件自动隐藏——浏览器不直连第三方。
- **地理位置**（修复前）：读设置键 `home.weather_city`——但该键**从未有过设置 UI**，实际永远为空，
  空 = 不带城市请求 wttr.in → 按**服务器出口 IP** 自动定位（NAS 在哪就显示哪）。

## 完成情况

1. **设置 UI**（设置 → 常规面板，随「常规设置」一并保存）：
   - 「天气城市」输入框：中文/英文城市名均可（`北京` / `Shanghai`），≤60 字符（后端既有校验）；
   - 留空 = 恢复服务器 IP 自动定位；
   - 「预览」按钮：走新加的 `?city=` 查询参数即时看该城市当前天气与三日预报，不打扰已保存值；
   - 说明文案注明数据来源与生效时机（保存后首页下次加载生效）。
2. **后端**（monitor.py）：
   - `widget_weather` 增加可选 `city` 查询参数（登录用户可用），优先于设置值；顺手百分号编码
     中文城市名（此前 f-string 直拼，中文未经编码依赖 httpx 兜底）；
   - **修存量 bug**：设置读取误用原始 `row.value`（JSON 串，字符串值带双引号）→ 改 `get_value()`；
     实测带引号的 `"北京"` 会让 wttr.in 404——此 bug 因该键从无 UI 从未被触发过。
3. **前端**：`appsEnhApi.weather(city)` 可选参数；保存链路并入 `saveGeneral` 载荷；
   预览结果卡（城市/现温/三日区间）用令牌样式。
4. **测试**：`test_weather_city.py` 3 例——设置值生效+中文编码+query 参数优先 / 上游异常返回 null
   （不 500）/ 设置校验 61 字符 422。httpx 外呼用 MockTransport 注入（test_p13 同款手法）。

## 测试结果

- 后端：全量 **241 passed / 2 skipped**（新增 3 例），ruff ✅；
- 前端：vitest 57/57 ✅、eslint ✅、build（vue-tsc）✅；
- 本地浏览器 E2E（localhost:5173 + 本地 8000，localadmin）：常规面板填「北京」→ 预览返回
  Beijing 实时天气（20°C Smoky haze + 三日）→ 保存 → 首页组件显示 `Beijing · Smoky haze · 体感 17°C` ✅；
  - 过程中发现本地 8000 后端为无 --reload 的旧进程（新参数被忽略），已重启为 --reload 方式。

## 关键决策

1. 地理设定维持「显式城市名」而非经纬度/IP 定位开关：wttr.in 免 key 场景下城市名最直观；
   留空即原自动定位行为，零迁移成本；
2. 预览用 query 参数而非草稿写库：无副作用、失败即示，不污染其他端；
3. 天气失败语义保持"静默隐藏组件"，预览路径才显式报错——首页不打扰、设置页可诊断。

## 遗留

- wttr.in 为公共免费服务，无 SLA；若后续不稳可加 open-meteo 等备选源（设置里可扩展"数据源"）；
- 城市名合法性完全交给 wttr.in（预览可发现），未做本地城市库校验。
