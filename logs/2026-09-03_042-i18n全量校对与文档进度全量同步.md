### 一、i18n 校对（zh-CN 440 key = en 440 key，占位符零不一致）

**代码引用但语言包缺失（8 个，此前 UI 会直接渲染 key 原文）**：

| key | 引用处 | 补充文案（zh / en） |
|---|---|---|
| `home.statusUp` | HomeView、MonitorView | 在线 / Online |
| `home.statusDown` | HomeView、MonitorView | 离线 / Offline |
| `home.statusUnknown` | HomeView | 未知 / Unknown |
| `settings.timezone` | SettingsView | 时区 / Timezone |
| `settings.followSystem` | SettingsView | 跟随系统 / Follow system |

**两包不对称（4 处）**：en 缺 `settings.menuUsers`、`settings.usersHint`、`users.enabled`（en 已补）；en 独有死键 `common.noData2`（零引用，已从 en 删除）。

**硬编码文案（2 处）**：SettingsView Logo 占位符 `（留空显示站点名）`→ `settings.logoUrlPh`；MonitorView 温度告警 `≥ {{ s.high }}°C 注意` → `monitor.tempHigh`（`{temp}` 占位符）。

**校对方法**：esbuild 加载两份语言包全量展开 diff key + 占位符；正则反查源码全部 `t('...')`/`$t('...')` 引用；动态拼接 key（`monitor.block.*`、`monitor.range.*`、`env.state*`、`apps.urlType.*`、`home.greet*`、三元表达式取 key）逐一人工核实，避免误报死键。

**结论保留项**：语言下拉的 `简体中文`/`English` 按惯例以母语显示，不算漏翻；`formatUptime` 已内置 zh/en 双分支；`login.timezone`/`login.followSystem` 等约 30 个 key 当前零引用（疑似重构遗留），本次不动、仅记录。

## 关键决策

1. **动态 key 不清理**：模板拼接/三元取 key 使静态扫描不可靠，"疑似死键"约 30 个仅记录不删，避免误伤；
2. **`visibility.public` 译名**：依据 api-spec「public=所有人（含访客）」定 zh 文案，不造新词；
3. **进度口径沿用 55/120**：不重推导（含 P4 已移除的 4.8 口径差异 ±1），以规模总览三处一致为准；
4. **api-spec 表数**：以 §3 逐表清点 32 为准，README 原有 32 是对的、api-spec 自身 31 是滞后；
5. 文档只同步状态/数字/排期，不动契约内容，均不升版本号（无契约变更）。
