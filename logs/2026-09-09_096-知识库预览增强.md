# 096 · 知识库预览增强：Office 组件库渲染 + zip 条目预览 + 垃圾文件过滤

## 需求原意

用户在 NAS 实际使用「沈阳航空航天大学」知识源后反馈：
1. 很多文件不能加载，.doc 打不开；
2. docx 显示形式不对（与 Word 打开效果差距大）；
3. zip 好像会自动下载（希望可预览）；
4. 很多文件类型的预览效果都有问题，Office 系列应该用专门的组件库。
（并提供 admin 账号允许创建专属管理员账号——已建 `kbagent`。）

## 实际文件调研（沈航源）

PDF（大量，含 130MB 教材）、docx（多篇观后感/申请）、.doc 老格式（任务书/检索报告）、
zip（实验报告/系统截图）、pptx（影alien说赏析）、png、desktop.ini 与 @eaDir 垃圾项。

## 完成情况

### 1. Office 预览改前端组件库（用户建议方向）

- **docx → docx-preview**：Word 页面级高保真渲染（版式/字体/居中/页面纸感），
  替换此前 mammoth 裸 HTML（显示形式不对的根因）；
- **xlsx/xls → SheetJS（xlsx 0.18.5）**：逐 sheet 转 HTML 表格（.xls 老格式顺带支持预览）；
- **pptx → pptx-preview**：幻灯片按原始版式渲染（黑底/图片/文字排版完整还原，实测效果佳）；
- 三库均为动态 import 懒加载（打开对应文件才加载分块），失败显示 warning 并给下载兜底；
- 服务端 mammoth/openpyxl/python-pptx 转换链路移除（knowledge_office.py 删除，
  requirements 移除三依赖，镜像瘦身）；test_04 断言改为仅校验类型分发。

### 2. zip 条目预览

- `.zip` 识别为独立类型；`read` 返回条目清单（名称/原始大小/压缩后大小，跳过目录与
  __MACOSX）；前端条目表 + 每条「预览（新标签页）/下载」；
- 新端点 `GET /knowledge/{id}/zip-entry?path=&entry=`：内存提取单文件流（按扩展名给
  Content-Type），鉴权同 raw（Authorization 头或 exp+sig 签名，签名串 `path!entry`）。

### 3. 垃圾项过滤

树与清单不再出现 `@eaDir`（群晖缩略图目录）、`desktop.ini`、`Thumbs.db`。

### 4. 环境与账号

- 按用户授权创建专属管理员 `kbagent / Kbage2026`（全部操作以此账号进行）。

## 测试结果

- 后端：全量 **255 passed / 2 skipped**，ruff ✅；
- 前端：vitest 57/57 ✅、eslint ✅、build ✅；
- NAS 实测（kbagent 登录，沈航源）：
  - **docx**：docx-preview 页面级渲染，与 Word 打开观感一致 ✅；
  - **zip**：汽车销售系统.zip 条目表 16 项全部列出，预览/下载可用 ✅；
  - **pptx**：辛德勒的名单.pptx 幻灯片按原始版式渲染（图片/标题/排版还原）✅；
  - **树**：desktop.ini/@eaDir 已过滤 ✅；.doc 仍为下载兜底（见遗留）。

## 关键决策

1. Office 预览从前端组件库走而非服务端转换：保真度高（docx-preview/pptx-preview 按原始
   版式渲染）、免服务端转换失败、依赖懒加载不影响首屏；.xls 由 SheetJS 顺带支持；
2. zip 预览用服务端条目清单 + 单文件流：zipfile 标准库零依赖，条目表/提取均可控。

## 遗留

- **.doc / .ppt 老格式**无可靠纯 JS/纯 Python 渲染方案，维持下载兜底；如需在线预览须上
  LibreOffice 转换服务（镜像 +700MB），待定；
- zip 单文件预览对大文件（>200MB）拒绝提取；pptx-preview 依赖 chunk 较大（懒加载可接受）。
