# 工作日志 · 2026-09-01 · 002：服务器监控功能强化

## 需求（用户原意）

最主要的还是要加入**服务器性能监控、端口监控**等等有关服务器相关的功能，这些都要有。

## 完成情况

《Portal 功能详述》升级到 **v1.1**（`docs/feature-spec.md` 与 `docs/feature-spec.html` 同步更新）：

1. **新增 M17 · 服务器性能监控**（★ 核心模块，21 个功能点）：
   - M1 即落地基础：系统信息概览（OS/内核/负载/运行时长）、每核 CPU、内存/Swap、磁盘空间与 inode、各网卡流量、ECharts 历史图表、采样存储与自动清理、WebSocket 秒级刷新、独立监控仪表盘页；
   - M2 增强：磁盘 IO/IOPS、温度、进程 Top 榜、按容器的资源占用、资源阈值告警与自定义告警规则；
   - M3 进阶：历史数据 CSV 导出、Web SSH 终端（xterm.js）、多机监控 Agent、SNMP 采集、监控大屏、性能报表。
2. **新增 M18 · 端口监控**（★ 核心模块，12 个功能点）：端口监听清单（进程级自动发现）、任意 host:port 探活、端口通断变更告警（可挂 Flow）、端口-应用双向关联、端口占用检索（排查冲突）、批量导入、总览看板；M3 扩展延迟曲线、监听变更历史、裸露端口（0.0.0.0 监听）安全提示、内网/外网可达性对比、分组标签。
3. **M07 重构**：由"监控与探活"调整为"应用探活与可用性"（7 个功能点），只保留应用级探活/可用率/证书与域名监控，NAS 资源类能力全部并入 M17，避免职责重叠。
4. **阶段规划调整**：服务器监控基础（M17-1~9）纳入 M1 验收；M2 增加阈值告警与端口监控；M2 验收场景从 4 个升级为 5 个（新增服务器指标阈值告警、端口断通告警）；首页"NAS 资源速览"小组件提前到 M1。
5. **规模变化**：16 模块/192 功能点 → **18 模块/220 功能点**；总览表、目录、统计卡、新增清单（新增第 23~25 条）均已同步。

## 关键决策

1. **监控拆分为三层职责**：M07 管"应用死活"、M17 管"整机性能"、M18 管"端口网络层"，边界清晰不重复；
2. **M17 基础能力进 M1**：用户明确服务器监控是最主要能力，故监控页与基础采集随 MVP 交付，而非推迟到 M2；
3. 采集技术路线：容器挂载宿主机只读 `/proc`、`/sys`（psutil 指向宿主数据源），`docker stats` 兜底，群晖 DSM 等 NAS 专属 API 作为增强适配；
4. `design-proposal` 保持 v0.1 不动（历史版本），功能细节以 `feature-spec` 版本演进为准。
