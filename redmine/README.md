# redmine/ · Redmine 任务导入文件

本目录存放 Portal 开发任务的 **Redmine 导入文件**，内容与《开发计划 dev-plan》v1.1 完全对应（24 个阶段 / 108 个步骤 + 24 个阶段验收任务）。

## 文件说明

| 文件 | 内容 |
|---|---|
| `portal-tasks.csv` | 全部任务（UTF-8 BOM，Excel 可直接打开）：每个阶段 1 条"阶段验收"任务（描述内含单测/业务测试关卡与退出标准）+ 每个步骤 1 条任务 |

## 任务命名规则

- 步骤任务主题：`[P0] 0.1 仓库与目录结构`（阶段号 + dev-plan 步骤编号 + 名称）
- 阶段验收任务主题：`[P0] 阶段验收：项目脚手架与基础设施`（优先级=高）
- 任务描述中标注了**关联功能点编号**（如 M04-10），与 feature-spec 对应

## Redmine 侧准备（一次性）

1. 创建项目（如 `portal`）；
2. 版本（路线图）：新建 `M1-MVP`、`M2-增强`、`M3-进阶` 三个版本；
3. 跟踪标签：确保存在 `任务`（默认一般都有）。

## 导入步骤

1. 进入项目 → **管理 → 导入 → 问题**；
2. 选择 `portal-tasks.csv`，文件编码 **UTF-8**，分隔符逗号；
3. 字段映射：`主题→主题`、`跟踪→跟踪`、`状态→状态`、`优先级→优先级`、`目标版本→目标版本`、`描述→描述`；
4. 导入后可在问题列表按"目标版本"筛选 M1，按阶段前缀 `[P0]` 排序建立父子关系（可选）。

## 与开发计划的关系

- **dev-plan.md/.html 是唯一进度真相源**（步骤级 ⬜/🔄/✅ 状态）；
- Redmine 用于评审流转与缺陷跟踪，两者通过任务主题中的 `[P阶段] 步骤号` 对应；
- 开发完成一个步骤：先更新 dev-plan 状态，再在 Redmine 勾选对应任务。
