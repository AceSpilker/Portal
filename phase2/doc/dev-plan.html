Portal 二期开发计划 · Django × Art Design Pro

二期执行的唯一依据：把《二期迁移方案》（Django 5.2 + Django Ninja + Channels 后端、Art Design Pro v3.0.2 前端、nginx+backend 双容器部署）拆解为「里程碑 → 阶段 → 步骤」的执行清单。20 个阶段 · 171 个步骤 · 3 个里程碑 · 每阶段双测试关卡。功能基线为一期 feature-spec v1.6 的 220 功能点，1:1 对齐不增不减。

1文档定位与使用约定

  • 文档分工：《迁移方案》回答"做什么、为什么这样选"；本计划回答"按什么顺序做、每步做到什么程度、怎么验收"。端点/表/任务等底层数据以迁移方案 §4–§9 与一期盘点为依据，不在本文重复展开。
  • 状态图例：⬜ 未开始 ｜ 🔄 进行中 ｜ ✅ 已完成（须通过该阶段两道关卡）｜ ⛔ 阻塞（注明原因）。
  • 双测试关卡（沿用一期约定，每阶段关闭条件）：
    • 关卡A 单元/接口测试：pytest-django（后端）与 vitest（前端）对应用例集全绿，覆盖率不低于一期同域基线；
    • 关卡B 业务功能测试：按该阶段清单手工/脚本执行通过，涉及真机项（NAS/路由器/外网渠道）标注执行环境。
  • 状态更新：完成一步 → 状态 ⬜→✅ 并在根 logs/ 记一笔（需求/完成/决策/遗留）；阶段内步骤全 ✅ 且双关卡通过 → 阶段 ✅。
  • 一期冻结：二期全程不改动 backend/ 与 frontend/；所有二期代码位于 phase2/。

3测试策略总则

  1. 单元/接口测试：后端 pytest-django 连临时 SQLite + SECURITY__ENCRYPT_ENABLED=false（同一期 conftest 三件套），FakeSession（模拟前端 WebCrypto 信封）自 D0 起可用；前端 Vitest 覆盖纯函数与 http 层分支。
  2. 一期用例迁移：一期 42 个测试文件按域映射到 D2–D7 各阶段（阶段表内注明），断言按二期原生契约（code==200 / msg）改写，等量迁移是硬要求——D8 收口核对总数不少于一期基线（288）。
  3. 契约自动化：D8 用一期 OpenAPI 与二期 Ninja Schema 的自动 diff 代替人工核对 285 端点。
  4. 真机项：扫描（192.168.5.0/24）、SNMP/路由器、MySQL@3309 查看器、通知渠道真发、NAS 部署——标注「真机」，在 NAS 环境执行并记录。
  5. 覆盖率门禁：后端全局 ≥70%、core/services ≥80%（同一期）；前端 build + vue-tsc 零错误为 F 系关卡 A 组成部分。
