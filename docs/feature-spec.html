M01认证与账户 15 项

定位：系统的安全底座。MVP 只做"够用且安全"，企业级登录方式放在 M3。

#功能点说明阶段
1登录页用户名 + 密码，支持"记住我"（延长 refresh 有效期）M1
2首次初始化向导系统无用户时进入引导页：创建管理员 → 站点命名 → 完成M1
3JWT 认证access（30min）+ refresh（7d），前端拦截器自动续期，登出即失效M1
4修改密码校验旧密码；改密后其他会话强制下线M1
5密码强度校验长度 ≥ 8 且含字母数字，弱密码拒绝M1
6登录失败限速同 IP 5 次/分钟失败即临时锁定，防爆破M1
7TOTP 两步验证绑定扫码（otpauth 二维码）+ 恢复码；可全局强制开启M2
8会话/设备管理查看当前登录设备列表（IP/时间/UA），可单个踢出M2
9角色权限admin（全部）/ user（首页 + 个人偏好），见权限矩阵M1
10访客模式开启后免登录可看首页，仅展示"公开"标记的应用M2
11用户管理管理员增删用户、重置密码、禁用账号M2
12OIDC / LDAP 登录对接公司单点登录 / 企业 LDAP，账号自动映射M3
13Passkey 免密登录WebAuthn 指纹/Face ID 登录（可选）M3
14审计日志记录登录、配置变更、容器操作、Flow 执行，可筛选导出M2
15传输加密 ★应用层端到端加密：RSA-3072 会话密钥交换 + AES-256-GCM 信封，/api 请求体/响应体/Authorization 头全部密文传输，HTTPS 之外的第二道保障；豁免 health/握手/静态资源；nonce 重放防护✅

M04多访问方式管理 ★ 核心 18 项

定位：本系统差异化核心——解决"同一个服务，在家、在公司、在外网要用不同地址访问"的问题。

#功能点说明阶段
1入口管理每个应用可挂 1..N 个访问入口：类型 + 地址 + 标签 + 排序M1
2入口类型：域名 domain公网/域名地址（走反向代理），如 https://jf.example.comM1
3入口类型：内网 lan内网 IP:Port 直连，如 http://192.168.1.10:8096M1
4入口类型：SSH 隧道 ssh经跳板机访问，配合功能 15/16 使用M1
5入口类型：VPN vpnVPN 网段地址，如 http://10.8.0.1:8096M1
6入口类型：自定义 custom任意地址 + 自定义说明M1
7网络环境档案定义环境（家庭内网/公司/VPN…）：名称 + CIDR + 入口优先顺序 + 是否默认兜底M1
8环境自动识别后端按请求来源 IP 匹配 CIDR 判定当前环境；未命中走默认档案M1
9环境手动切换器顶栏环境徽标，可手动覆盖自动识别结果，选择被记忆M1
10智能解析GET /api/apps/{id}/resolve：按当前环境的入口优先级返回推荐入口 + 备选列表M1
11点击前预检可选：打开前快速 TCP/HTTP 探测推荐入口（500ms 超时），不通自动给备选M2
12多入口选择浮层可按应用配置"点击弹层手选"，浮层内标注每个入口适用的环境与状态M1
13连通性测试矩阵设置页一键探测全部入口，输出 应用×入口 的通断/延迟矩阵M1
14入口历史延迟记录每次探测延迟，查看趋势图定位"哪条线路慢"M2
15SSH 本地命令模式为 ssh 入口生成现成命令 ssh -L 18096:内网:端口 user@jump，弹窗一键复制后打开本地端口M1
16SSH 服务端托管隧道后端 asyncssh 维护隧道，门户提供 /tunnel/{id} 反代路径，点击直达；空闲超时断开；支持密码/私钥M2
17入口二维码为当前环境的入口生成二维码，手机扫码直达（配 PWA 体验极佳）M2
18环境探测调试页显示"服务器看到的你的 IP、命中的档案、各档案匹配结果"，方便排查识别不准M2
关键规则：
  • 未配置任何环境档案时，系统退化为普通面板（直接打开第一个入口），零配置可用；
  • 环境识别优先级：手动选择 > 自动识别，手动选择存于用户偏好；
  • 预检失败回退严格按该环境的入口优先顺序，全部不可用时提示"当前环境可能无法访问该应用"。

M06Flow 自动化 19 项

定位：轻量版 n8n/IFTTT。M2 用"触发器→条件→动作"表单编排快速落地，M3 升级画布。

#功能点说明阶段
1Flow 列表全部 Flow 一览：状态开关、最近执行、手动运行按钮M2
2表单式编排下拉选择触发器/条件/动作并填参数，上下拖拽排序M2
3画布编排Vue Flow 拖拽节点、连线、分支并行、节点内联调试M3
4触发器：定时 cron可视化选择（每 N 分钟/每天 HH:mm/自定义 cron）M2
5触发器：Webhook自动生成随机 token URL POST /api/hooks/flow/{token}，可吊销重置M2
6触发器：手动列表/详情一键运行M2
7触发器：事件应用离线/恢复、CPU/内存/磁盘超阈值、容器启停、通知事件M2
8条件节点表达式引用上游输出，如 prev.status_code == 200，不满足则跳过后续M2
9动作：HTTP 请求method/url/headers/body，常用于联动其他服务 APIM2
10动作：通知推送发送到指定通知渠道，标题/内容支持变量插值M2
11动作：SSH 命令指定主机（复用凭据库）执行命令，返回输出M3
12动作：Docker 操作容器 start/stop/restartM3
13动作：AI 调用把上游输出交给 AI 处理（总结/判断），结果继续向下游传递M3
14动作：延时/变量等待 N 秒；设置/修改变量供后续节点引用M3
15试运行 dry-run不真正执行副作用动作，逐步显示"将执行什么、输出是什么"M2
16执行历史每次执行记录状态/耗时/每步输入输出日志，可重看M2
17失败重试失败自动重试 N 次、间隔 M 秒，可配置M2
18失败告警Flow 执行失败自动推送通知渠道M2
19模板/导入导出内置常用模板（下载完成通知、离线自动重启等），支持 JSON 导入导出分享M3
典型场景：
  • 每天 08:00 查询 qBittorrent 完成数 → 有新增则 Bark 推送"昨夜新增下载 X 个"；
  • 探活发现 Jellyfin 离线 → Docker 自动重启 → 仍失败升级为 error 通知；
  • 手机快捷指令 POST Webhook → AI 总结剪贴板文本 → 推回 Telegram。

M17服务器性能监控 ★ 核心 21 项

定位：NAS 整机的"体检中心"，也是本项目最高优先级模块——性能、资源、进程一目了然。基础能力随 M1 落地，不是"以后再说"的可选项。

#功能点说明阶段
1系统信息概览主机名/操作系统/内核版本/架构/运行时长/实时负载（1/5/15min）M1
2CPU 监控总使用率 + 每核使用率曲线 + 负载均值M1
3内存监控已用/可用/缓存/缓冲/Swap 使用率M1
4磁盘空间监控各分区/挂载点的容量、已用、使用率与 inode 用量M1
5网络流量监控各网卡实时上下行速率、当日/累计流量统计M1
6资源历史图表全指标历史曲线（ECharts），实时 + 24h/7d/30d 区间切换M1
7采样存储与自动清理默认每分钟采样入库，保留天数可配（默认 7 天）自动清理M1
8实时刷新推送监控数据经 WebSocket 秒级推送，无需手动刷新M1
9监控仪表盘页独立"监控"页，一屏看全部指标 + 应用状态M1
10磁盘 IO 监控各磁盘读写速率、IOPS、IO 利用率M2
11温度监控CPU/主板/硬盘温度（依赖传感器可用性，无传感器自动隐藏）M2
12进程监控按 CPU/内存排序的进程 Top 榜（PID/用户/命令行），支持搜索M2
13Docker 资源占用按容器维度统计 CPU/内存/网络（联动 M08）M2
14资源阈值告警CPU/内存/磁盘用量超阈值持续 N 分钟 → 推送通知M2
15告警规则自定义每项指标独立配置阈值/持续时间/通知级别，可单独启停M2

  • M03 基础（1~6, 8, 9, 13）：应用与分组 CRUD、图标、状态点、导入导出
