Art Design Pro 前端重构 · 框架分析报告

为 Portal（NAS 门户系统）引入 Art Design Pro v3.0.2 管理后台框架，替代现有手写布局的 Element Plus 前端，功能保持一致。本报告对框架与现有前端做全量对照分析，给出能力映射、差距清单与迁移方案。

报告版本 v1.0 2026-10-21 框架 Art Design Pro v3.0.2 新目录 frontend-artdesign/ 功能对齐现有 frontend/（16 视图）

1背景与结论速览

1.1 任务与产出

在 Portal 项目内新建 frontend-artdesign/ 目录，从 GitHub 拉取 Art Design Pro 最新版本，作为下一代前端（v2）的开发底座；功能与现有 frontend/（v1，120/120 步骤全部完成的 v1.0 发布版）保持一致。本阶段产出：

  • ✅ 框架已拉取：git clone --depth 1 https://github.com/Daymychen/art-design-pro.git frontend-artdesign，最新提交 f3aaf58（2026-06-01），框架版本 v3.0.2；目录内保留上游 .git，便于后续跟踪上游更新（也可移除后并入 Portal 主仓库管理）。
  • ✅ 框架全量结构分析（§2）。
  • ✅ 现有前端功能基线盘点（§3，迁移需求权威清单）。
  • ✅ 框架能力 ↔ Portal 需求映射（§4）、差距与风险（§5）、分阶段迁移方案（§6）。

1.2 结论速览

✅ 可行 —— 技术栈高度同源

同为 Vue 3 + TypeScript + Vite + Element Plus + Pinia + vue-i18n + ECharts 6 技术栈，组件层（Element Plus）几乎零学习成本；框架带来的多布局模式、明暗主题、多标签页、权限体系、表格/搜索表单范式均为净增值。

⚠️ 五处必须适配的硬差异

① 响应结构 {code,message,data}/code=0 vs 框架 {code,msg,data}/code=200；② Portal 的 RSA+AES-GCM 全链路加密请求层需整体移植；③ 认证模型（init 向导/TOTP/LDAP/OIDC/refresh）需重写登录页与 user store；④ vue-i18n 9 vs 11 与 locale 键名（zh vs zh-CN）；⑤ 路由为 hash 模式 + 字符串组件路径 + 动态注册机制。

🔴 需补装 / 自建的依赖能力

@vue-flow（Flow 画布）、@xterm（WebSSH）、docx-preview / pptx-preview（知识库 Office 预览）、marked + dompurify（Markdown 渲染）、vite-plugin-pwa（PWA）、vitest（单测）——框架均未内置；另需保留 4 条 WebSocket 与访客模式。

💡 总体判断：适合迁移。框架的布局/主题/权限/组件资产能显著提升 v2 的观感与开发效率；工作量集中在「请求加密层移植 + 认证流重写 + 16 个视图逐页迁移」三块，无技术死角。建议 v1 保留并行运行（同一后端），v2 按视图逐页替换验证。

2.4 框架自带功能

主题与外观

  • 明暗模式：Light / Dark / Auto 跟随系统；index.html 内联防白屏脚本；切换时自动生成主题色 9 级明暗变体 CSS 变量（src/hooks/core/useTheme.ts、src/utils/ui/colors.ts）。
  • 主题色：预设 7 色 + 自定义（运行时写 --el-color-primary-* 全套色阶）。
  • 菜单布局 4 种：左侧 / 顶部 / 混合（顶+左）/ 双栏菜单（MenuTypeEnum，渲染组件在 src/components/core/layouts/art-menus/）。
  • 菜单主题 3 种：design / dark / light；可调菜单宽度、全局圆角 customRadius、边框模式、容器宽度（100% / 盒式）、标签页样式、页面过渡动画（默认 slide-left）。
  • 设置面板：art-settings-panel/ 12 个 widget，支持「复制配置 / 重置」。

国际化

  • vue-i18n 9，legacy:false + globalInjection，zh / en 两个语言包（src/locales/langs/），导出全局 $t 供任意 ts 文件使用；Element Plus 文案经 ElConfigProvider 跟随（与 v1 同法）。

权限系统（双模式，VITE_ACCESS_MODE 切换）

  • frontend 模式（默认）：菜单来自 src/router/routes/asyncRoutes.ts → modules/*，登录后按 userStore.info.roles 递归过滤 meta.roles。
  • backend 模式：菜单由 GET /api/v3/system/menus 返回同构 JSON，同样走 MenuProcessor。
  • 路由守卫（src/router/guards/beforeEach.ts）：未登录跳登录 → 拉用户信息 → 动态 router.addRoute() → 权限校验 → 404 兜底；含初始化防死循环、并发防抖、401 自动登出。
  • 按钮权限：hasAuth('add') Hook + v-auth 指令（无权移除 DOM）+ v-roles 角色指令；演示角色 R_SUPER / R_ADMIN / R_USER。

核心组件（components/core，前缀 art-*）

  • 表格体系：art-table（ElTable 封装 + 内置分页 + 斑马纹/边框/表头配置）、art-table-header（列筛选/刷新/密度/列配置缓存）、useTable / useTableColumns / useTableHeight Hook —— Portal 的端口监控表、设备清单表、容器表可直接套用此范式。
  • 表单体系：art-form 配置化表单、art-search-bar 搜索表单（展开收起）—— 应用管理页的搜索过滤可直接替换。
  • 图表：ECharts 6 封装 10 种（bar/h-bar/dual-bar/line/ring/radar/scatter/k-line/map）+ 8 种图表卡片（stats/line/donut/progress/timeline…）—— 监控页 7 个数据块可改用图表卡片重组。
  • 布局/体验：多标签页 work-tab（固定/右键/恢复）、全局搜索 Ctrl+K（含历史）、通知中心、面包屑、锁屏（crypto-js）、全屏、水印、色弱模式、顶部进度条 NProgress、页面切换动画、keep-alive（meta.keepAlive + 动态 exclude）、iframe 路由管理、WebSocket 单例封装（心跳/重连/消息队列）、mitt 事件总线。

请求封装（src/utils/http/index.ts）

  • axios 实例：timeout 15s、baseURL=VITE_API_URL；请求拦截注入 Authorization: accessToken；响应拦截按 {code,msg,data} 且 code===200 解包，401 三秒防抖登出，408/5xx 可配重试；每请求可配 showErrorMessage / showSuccessMessage；错误文案 i18n（httpMsg 命名空间）。
  • request.get/post/put/del<T>() 直接返回 data 泛型 —— 接口清爽，但响应契约与 Portal 后端不同，必须改拦截器（见 §5-G1）。

Mock 方式

  • 无本地 mock 服务器：开发环境 Vite 把 /api 代理到远程 Apifox Mock（VITE_API_PROXY_URL）；另有 src/mock/temp/* 静态演示数据被 demo 页直接 import；pnpm clean:dev 一键精简 demo。

3.2 布局 / 路由 / 认证

  • AppLayout：单布局（侧栏 clamp(200px,16vw,216px)，<1080px 折叠 68px 图标栏）+ 顶栏（页面标题 + 通知中心铃铛 + Ctrl+K 命令面板 + 网络环境切换器（自动识别+手动覆盖））；导航按权限动态显隐（docker 需后端启用探测）；访客/登录/404 不套布局。
  • 路由：history 模式，静态导入全部视图；meta.public / meta.requiresAdmin 守卫。
  • Token：localStorage portal.token / portal.refresh / portal.user；access 30min 自动续期、refresh 7 天。

3.3 状态与 API 层

  • 6 个 store：auth（会话）、settings（全局设置 map）、env（网络环境档案）、notify（通知中心角标/列表/WS 事件）、probe（WS /ws/notify 长连接：探活帧+通知帧，指数退避重连 3s→60s）、iconLibrary（统一图标库，首次播种 Element 图标名）。
  • API 层 26 个模块 + request.ts + secure.ts，核心特征（迁移最大风险点）：
    • 传输加密：RSA 公钥握手 → 前端生成 AES-256-GCM 会话密钥 → RSA-OAEP 封装上报；密钥仅存内存；Authorization: ENC <nonce>:<payload> 加密头 + X-Session-Id + 请求体信封加密；三条明文降级路径（HTTP / 服务端 ENCRYPT_ENABLED=false / 握手异常）。
    • 响应契约：{code,message,data}，code=0 成功；1100 会话失效 → 重握手重试一次；401 → refresh 静默续期一次重试（并发去重），失败登出跳登录；1007=TOTP。
  • 4 条 WebSocket（token 走 URL query，均需保留）：/ws/notify（probe store）、/ws/monitor、/ws/ai-chat、/ws/ssh-terminal。dev 代理四条：/api /ws /icons /tunnel → 8000。

3.4 国际化 / 主题 / 测试 / 其它

  • i18n：zh-CN / en，各 1370 行、37 个顶级命名空间；Accept-Language 跟随后端文案；切换入口在设置页。
  • 主题：单文件设计系统（253 行 CSS 变量双套 + .glass 毛玻璃 + .brand-text 渐变）；html.dark；主题色运行时派生 EP 全套色阶；壁纸层（纯色/渐变/图片+模糊+遮罩）+ 自定义 CSS 注入（appearance.custom_css）。
  • PWA：vite-plugin-pwa（autoUpdate/standalone/4MB 预缓存上限/denylist /api /ws /files /icons）。
  • 测试：vitest + jsdom，13 个纯函数单测文件 50+ 用例（router 守卫/layout 序列化/theme 色阶/ssh 命令/协议拆拼/命令面板搜索/工具函数等）。
  • 关键 utils/composables：layout（首页布局序列化契约）、search（命令面板子序列模糊+权重）、useOpenApp（应用打开编排单例）、useTheme、protocolUrl、canvas（Flow 线性↔图互转，与后端同构）、export 文件名规范等 14 个模块。

5差距清单与风险

#差距 / 风险等级影响与对策
G1响应契约不同：{code,msg,data}=200 vs Portal {code,message,data}=0高不改后端的前提下，重写 src/utils/http/index.ts 响应拦截（解包字段、成功码、业务 Error 携 code）；错误文案 i18n 改挂 Portal message 直传
G2加密传输层（RSA 握手 + AES-GCM 信封 + ENC 头 + 1100 重握手 + 401 静默续期）高v1 的 secure.ts 与拦截器逻辑整体移植；框架的 Authorization 注入/401 登出/重试逻辑被其取代；明文降级三路径 + 一次性警告需保留（App.vue 挂载）
G3认证流差异：框架期望 {token,refreshToken} + /api/user/info 返 roles/buttons高重写 src/api/auth.ts 与 user store：登录走 Portal /api/auth/*（含 init/TOTP/LDAP/OIDC），用户信息映射 admin→R_ADMIN；refresh 并发去重逻辑移植
G4路由机制：hash 模式 + component 字符串路径 + 动态注册中16 个视图改写为 modules 模块（component: '/home' 字符串指向 views）；hash vs history 需决策（§8-Q1：后端/Docker 未绑 history 回退，hash 反而省事；但 URL 带 # 与 v1 不一致）；守卫的 requiresAdmin → meta.roles
G5vue-i18n 9（legacy:false 可用 Composition API）vs v1 的 v11中API 大体兼容；$t 全局导出方式框架已解决；1370×2 行文案 + 37 命名空间需脚本化搬迁（zh-CN→zh 键名、ts→json）
G6缺依赖：@vue-flow、@xterm、docx-preview、pptx-preview、marked、dompurify、qrcode、dayjs、vite-plugin-pwa、vitest中pnpm add 一次补齐（xlsx/vue-draggable-plus/echarts 框架已有）；vite.config 加 PWA 插件与 /ws /icons /tunnel 代理
G7localStorage 键与持久化机制不同（sys-v{ver}-* vs portal.*）低v1 与 v2 并行期互不干扰（天然隔离）；v2 内部沿用 StorageKeyManager 即可；跨版本不共享登录态可接受
G8首页「每标签独立布局」与框架 keep-alive/多标签页交互低首页业务 Tab 用 v1 /me/tabs 机制；框架 work-tab 的 keepAliveExclude 不影响；首页磁贴拖拽组件直搬
G9docker 导航动态显隐（后端启用探测）低守卫后按 /docker/status 结果改 menuStore.menuList 或用 meta 动态标记
G10Node ≥ 20.19 + pnpm 强制低本机需 pnpm（npm 不可用，engines 约束）；Dockerfile 构建段相应改 pnpm；Node 20.19+ 镜像
G11v1 已知隐患：AiView marked 直出 v-html 未 sanitize修复迁移时统一 DOMPurify.sanitize，顺带消除隐患
G12demo 页面与 mock 数据清理低pnpm clean:dev 一键精简后仍需手工删 views 多余模块 + 路由 modules + 语言包 menus 段
⚠️ 最大风险集中在 G1+G2+G3（请求/加密/认证三件套）——它们是所有页面共同的地基，必须最先做且要有真机联调验证（后端 8000 + 加密握手 + 1100/401 分支）。建议以「登录 → 拉设置 → 首页磁贴」为最小贯通里程碑。
