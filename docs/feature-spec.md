# Portal · 功能详述（Feature Spec）

> **版本**：v1.5 ｜ **日期**：2026-09-01 ｜ **关联文档**：《Portal 总体设计方案（design-proposal）》v0.5
>
> **v1.1 变更**：按评审意见新增 **M17 服务器性能监控**、**M18 端口监控** 两个重点模块；M07 调整为聚焦"应用探活与可用性"，NAS 资源类能力并入 M17。
>
> **v1.2 变更**：数据库策略调整——**SQLite 为运行主库，定时镜像推送到 NAS 上的 MySQL**（灾备/集中存储）；M15 新增"MySQL 数据同步"功能点。
>
> **v1.3 变更**：移动端 UI 方案定稿（响应式 + 底部 Tab + 安全区适配，方案见《总体设计方案》§6.3）；M16 新增"安全区与手势适配"功能点。
>
> **v1.4 变更**：M01 新增"**传输加密**"功能点（应用层 RSA+AES-GCM 信封，HTTP 下数据不明文传输；协议见 api-spec §7）。
>
> **v1.5 变更**：M15 新增"**系统日志中心**"功能点（登录/操作/系统事件统一日志列表页）；M01-11 用户管理描述扩充（用户列表/新增/编辑/禁用/重置密码/角色分配/强制下线）。
>
> **文档定位**：本文档是 Portal 系统的**功能清单与功能细节**的权威来源，按模块列出全部功能点、交互规则与落地阶段。总体架构、技术选型、数据模型、部署方案见《总体设计方案》，两份文档配合阅读。本文与 HTML 版内容一致，**评审以 HTML 版为准**。

**图例**：`M1` = MVP 必做 ｜ `M2` = 第二阶段 ｜ `M3` = 进阶/远期 ｜ `可选` = 按需启用的独立模块 ｜ `★` = 差异化核心

**规模总览**：18 个功能模块 · **224 个功能点**

## 2. 模块详述

### M01 认证与账户（15 个功能点）

定位：系统的安全底座。MVP 只做"够用且安全"，企业级登录方式放在 M3。

| # | 功能点 | 说明 | 阶段 |
|---|---|---|---|

| 2 | 首次初始化向导 | 系统无用户时进入引导页：创建管理员 → 站点命名 → 完成 | M1 |
| 3 | JWT 认证 | access（30min）+ refresh（7d），前端拦截器自动续期，登出即失效 | M1 |
| 4 | 修改密码 | 校验旧密码；改密后其他会话强制下线 | M1 |
| 5 | 密码强度校验 | 长度 ≥ 8 且含字母数字，弱密码拒绝 | M1 |
| 6 | 登录失败限速 | 同 IP 5 次/分钟失败即临时锁定，防爆破 | M1 |
| 7 | TOTP 两步验证 | 绑定扫码（otpauth 二维码）+ 恢复码；可全局强制开启 | M2 |
| 8 | 会话/设备管理 | 查看当前登录设备列表（IP/时间/UA），可单个踢出 | M2 |
| 9 | 角色权限 | admin（全部）/ user（首页 + 个人偏好），见 §3 权限矩阵 | M1 |
| 10 | 访客模式 | 开启后免登录可看首页，仅展示"公开"标记的应用 | M2 |

| 12 | OIDC / LDAP 登录 | 对接公司单点登录 / 企业 LDAP，账号自动映射 | M3 |
| 13 | Passkey 免密登录 | WebAuthn 指纹/Face ID 登录（可选） | M3 |
| 14 | 审计日志 | 记录登录、配置变更、容器操作、Flow 执行，可筛选导出 | M2 |
| 15 | 传输加密 | 应用层端到端加密：RSA-3072 会话密钥交换 + AES-256-GCM 信封，/api 请求体/响应体/Authorization 头全部密文传输，HTTPS 之外的第二道保障；豁免 health/握手/静态资源；nonce 重放防护 | P24 ✅ |

### M04 多访问方式管理 ★（18 个功能点）

定位：**本系统差异化核心**——解决"同一个服务，在家、在公司、在外网要用不同地址访问"的问题。

| # | 功能点 | 说明 | 阶段 |
|---|---|---|---|
| 1 | 入口管理 | 每个应用可挂 1..N 个访问入口：类型 + 地址 + 标签 + 排序 | M1 |
| 2 | 入口类型：域名 domain | 公网/域名地址（走反向代理），如 `https://jf.example.com` | M1 |
| 3 | 入口类型：内网 lan | 内网 IP:Port 直连，如 `http://192.168.1.10:8096` | M1 |
| 4 | 入口类型：SSH 隧道 ssh | 经跳板机访问，配合功能 15/16 使用 | M1 |
| 5 | 入口类型：VPN vpn | VPN 网段地址，如 `http://10.8.0.1:8096` | M1 |
| 6 | 入口类型：自定义 custom | 任意地址 + 自定义说明 | M1 |
| 7 | 网络环境档案 | 定义环境（家庭内网/公司/VPN…）：名称 + CIDR + 入口优先顺序 + 是否默认兜底 | M1 |
| 8 | 环境自动识别 | 后端按请求来源 IP 匹配 CIDR 判定当前环境；未命中走默认档案 | M1 |
| 9 | 环境手动切换器 | 顶栏环境徽标，可手动覆盖自动识别结果，选择被记忆 | M1 |
| 10 | 智能解析 | `GET /api/apps/{id}/resolve`：按当前环境的入口优先级返回推荐入口 + 备选列表 | M1 |
| 11 | 点击前预检 | 可选：打开前快速 TCP/HTTP 探测推荐入口（500ms 超时），不通自动给备选 | M2 |
| 12 | 多入口选择浮层 | 可按应用配置"点击弹层手选"，浮层内标注每个入口适用的环境与状态 | M1 |
| 13 | 连通性测试矩阵 | 设置页一键探测全部入口，输出 应用×入口 的通断/延迟矩阵 | M1 |
| 14 | 入口历史延迟 | 记录每次探测延迟，查看趋势图定位"哪条线路慢" | M2 |
| 15 | SSH 本地命令模式 | 为 ssh 入口生成现成命令 `ssh -L 18096:内网:端口 user@jump`，弹窗一键复制后打开本地端口 | M1 |
| 16 | SSH 服务端托管隧道 | 后端 asyncssh 维护隧道，门户提供 `/tunnel/{id}` 反代路径，点击直达；空闲超时断开；支持密码/私钥 | M2 |
| 17 | 入口二维码 | 为当前环境的入口生成二维码，手机扫码直达（配 PWA 体验极佳） | M2 |
| 18 | 环境探测调试页 | 显示"服务器看到的你的 IP、命中的档案、各档案匹配结果"，方便排查识别不准 | M2 |

关键规则：

- 未配置任何环境档案时，系统退化为普通面板（直接打开第一个入口），零配置可用；
- 环境识别与手动切换的优先级：**手动选择 > 自动识别**，手动选择存于用户偏好；
- 预检失败回退顺序严格按该环境的入口优先顺序，全部不可用时提示"当前环境可能无法访问该应用"。

### M06 Flow 自动化（19 个功能点）

定位：轻量版 n8n/IFTTT。M2 用"触发器→条件→动作"表单编排快速落地，M3 升级画布。

| # | 功能点 | 说明 | 阶段 |
|---|---|---|---|
| 1 | Flow 列表 | 全部 Flow 一览：状态开关、最近执行、手动运行按钮 | M2 |
| 2 | 表单式编排 | 下拉选择触发器/条件/动作并填参数，向上拖拽排序 | M2 |
| 3 | 画布编排 | Vue Flow 拖拽节点、连线、分支并行、节点内联调试 | M3 |
| 4 | 触发器：定时 cron | 可视化选择（每 N 分钟/每天 HH:mm/自定义 cron） | M2 |
| 5 | 触发器：Webhook | 自动生成随机 token URL `POST /api/hooks/flow/{token}`，可吊销重置 | M2 |
| 6 | 触发器：手动 | 列表/详情一键运行 | M2 |
| 7 | 触发器：事件 | 应用离线/恢复、CPU/内存/磁盘超阈值、容器启停、通知事件 | M2 |
| 8 | 条件节点 | 表达式引用上游输出，如 `prev.status_code == 200`，不满足则跳过后续 | M2 |
| 9 | 动作：HTTP 请求 | method/url/headers/body，常用于联动其他服务 API | M2 |
| 10 | 动作：通知推送 | 发送到指定通知渠道，标题/内容支持变量插值 | M2 |
| 11 | 动作：SSH 命令 | 指定主机（复用凭据库）执行命令，返回输出 | M3 |
| 12 | 动作：Docker 操作 | 容器 start/stop/restart | M3 |

| 14 | 动作：延时/变量 | 等待 N 秒；设置/修改变量供后续节点引用 | M3 |
| 15 | 试运行 dry-run | 不真正执行副作用动作，逐步显示"将执行什么、输出是什么" | M2 |
| 16 | 执行历史 | 每次执行记录状态/耗时/每步输入输出日志，可重看 | M2 |
| 17 | 失败重试 | 失败自动重试 N 次、间隔 M 秒，可配置 | M2 |
| 18 | 失败告警 | Flow 执行失败自动推送通知渠道 | M2 |

典型场景（文档内置说明）：

- 每天 08:00 查询 qBittorrent 完成数 → 有新增则 Bark 推送"昨夜新增下载 X 个"；

## 4. 阶段规划汇总

### M1 · MVP（第 1~3 周）—— "骨架 + 核心差异化"

- 项目骨架（前后端 + Docker 多阶段构建 + compose）
- M01 基础（1~6, 9）：登录、初始化向导、JWT、角色、防爆破
- M02 基础（1~4, 6, 9, 12, 18~21）：磁贴/分组/拖拽/搜索/收藏/资源速览/主题/暗色/壁纸/响应式
- M03 基础（1~6, 8, 9, 13, 16 部分）：应用与分组 CRUD、图标、状态点、导入导出
- **M04 核心（1~10, 12, 13, 15）**：多入口 + 环境档案 + 智能解析 + 测试矩阵 + SSH 本地命令
- M10 快速工具（1, 3, 5, 7, 8, 10）：轻量提升日用价值
- **M17 基础（1~9）**：系统信息/每核 CPU/内存/磁盘空间/网卡流量采集、历史图表、监控页与实时刷新
- M15 基础（1, 3, 4, 11）：常规/外观/访问方式/关于
- M16 基础（1, 3, 6）：响应式与底部导航

**验收**：NAS 单容器跑通——登录 → 模板/手动建应用并配多入口 → 住宅/公司两个网段访问自动切入口 → 磁贴搜索直达；监控页实时展示 NAS 的 CPU/内存/磁盘/网络曲线。

### M2 · 增强（第 4~6 周）—— "智能与运维能力"

- M05 AI 助手（1~14）：多 Provider、流式对话、意图导航、生成应用条目
