Portal × Art Design Pro · 前后端整体迁移方案

以后端全面适配 Art Design Pro v3.0.2 为方向，覆盖后端契约层改造（B1–B10）、新前端 v2 建设（F0–F7）、v1 并行兼容、部署与测试的端到端迁移方案。本文档承接《artdesign-analysis》分析报告，其中 G1/G3 的"改前端适配后端"路线按本方案决策调整为"改后端适配框架"。

方案版本 v1.0 2026-10-21 后端 285 端点 / 42 测试文件 前端 v2 = frontend-artdesign v1 并行可回滚

1目标与总体策略

1.1 方向决策与范围

决策：后端完全适配 Art Design Pro 框架的硬约定——凡框架源码默认耦合的契约（响应信封、认证端点、请求头格式），一律改后端；业务端点的数据形状（分页、字段命名）与框架无耦合，保持不动，由 v2 自有的 API 类型层消费。理由：框架硬约定只有 4 处、改动集中且可控（后端契约代码全部收敛在 response.py / auth.py / schemas / deps.py / middleware.py）；而 285 个业务端点若逐个改形状，收益为零、风险巨大。

本方案覆盖：后端契约改造 + 现存缺陷修复 + 部署链路（pnpm/Docker）+ 新前端 v2 全部建设内容 + v1 并行期兼容 + 测试与文档同步。不含：业务功能增删（功能 1:1 保持 feature-spec 基线）。

1.2 三条适配原则

  • 原则一（改后端）：框架拦截器/守卫写死的行为 → 改后端。成功码 code=200、错误字段 msg、登录入参 userName、登录响应 {token, refreshToken}、GET /api/user/info 返 {userId,userName,roles,buttons}、Authorization 无 Bearer 前缀。
  • 原则二（超集兼容）：后端响应采用新旧字段超集（登录同时返 token/refreshToken 与 access_token/refresh_token），旧字段不删——v1 前端登录/刷新链路零改动即继续可用。
  • 原则三（v2 自有层）：框架不管的部分（加密传输、4 条 WS、静默续期、分页形状、i18n 请求头）→ 在 v2 重写的 utils/http 与 API 模块层实现，移植 v1 成熟代码，后端不动。

1.3 全景图

B2 · 认证端点适配 必改 · 高

四个适配点，全部加法（超集），不破坏任何现有行为：

B2.1 登录入参别名（schemas/auth.py）

class LoginRequest(BaseModel):
    username: str | None = None
    password: str
    totp_code: str | None = None
    model_config = ConfigDict(populate_by_name=True)
    @model_validator(mode="before")
    @classmethod
    def _alias(cls, v):
        if isinstance(v, dict) and v.get("userName") and not v.get("username"):
            v["username"] = v["userName"]
        return v

ADP 登录页发 {userName, password}（api.d.ts LoginParams），v1 发 {username,…}——两种都接受。

B2.2 登录响应超集（TokenResponse + 4 个产出点）

TokenResponse 增加 token: str（= access_token 别名输出）与 refreshToken: str（pydantic @computed_field 或序列化别名）。产出点 4 处同步返回超集：POST /api/auth/init（auth.py L54-68）、POST /api/auth/login（L107-160）、POST /api/auth/oidc/callback（enterprise.py L148-198）、POST /api/auth/ldap/login（L209-253）。旧字段 access_token/refresh_token/token_type/user 全保留 → v1 登录链路零改动。

B2.3 新增 GET /api/user/info（auth.py，require 登录）

@router.get("/user/info")
async def user_info_for_adp(user = Depends(get_current_user)):
    return ok(data={
        "userId": user.id,
        "userName": user.username,
        "email": "",                       # Portal 无邮箱字段，占位
        "avatar": "",
        "roles": ["R_ADMIN"] if user.role == "admin" else ["R_USER"],
        "buttons": [],                     # Portal 无按钮级权限码，保留数组形态
    })

角色映射固定为 ADP 的菜单常量 R_ADMIN / R_USER（v2 路由 modules 的 meta.roles 用同名常量，settings/logs 等 161 个管理员端点对应页面标 roles: ["R_ADMIN"]）。GET /api/auth/me 保留原样给 v1 与 TOTP 面板用。

B2.4 Authorization 可选 Bearer 前缀（core/deps.py L73 附近）

ADP 拦截器原样发 token（无 Bearer）。get_auth_context 与 WS token 解析处改为：h.startswith("Bearer ") 则去前缀，否则整串即 token。同时兼容 v1（带 Bearer）与 v2 加密层内层格式。API Token plt_ 前缀分支（L20/L41-51）不受影响。

B3 · 审计中间件顺序修复 顺带修 · 现存缺陷

本次分析发现的现存缺陷：中间件注册顺序为 locale → Audit（外层） → Encryption → 路由（main.py L319-328）。加密开启（默认）时，请求到达审计中间件时 Authorization 仍是 ENC … 密文，_user_id_from_auth_header（audit_middleware.py L35-51）要求 Bearer 前缀 → 解析失败 → 加密部署下所有写操作审计日志 user_id=None（当前生产容器即此状态，测试因 conftest 关加密而未暴露）。

修法：调整 add_middleware 顺序，让 AuditMiddleware 位于加密层内侧（先 add Audit 再 add Encryption）：审计即可读到解密回填后的 Bearer <jwt>（加密中间件 L84-95 解密后回填 inner headers），响应侧仍能拿到真实 HTTP 状态码与 JSON 明文。1100/1101/1102 传输层错误响应不再进审计（本来就不是业务写操作，语义更正确）。补一条测试：加密开启下写操作 → audit_logs.user_id 正确（test_crypto.py 或新文件）。

F1 · 请求层与认证重写 核心攻坚

4.1 utils/http 重写（保留 ADP 外壳，注入 Portal 内核）

文件：frontend-artdesign/src/utils/http/index.ts（重写）+ src/api/secure.ts（从 v1 整体移植）。最终单请求生命周期：

请求发起 request.get/post<T>({url, params/data, …}) │ 豁免路径(/health /crypto /public)？──是──► 明文直发 │ secure.ensureSession(): /api/crypto/public-key → enabled? RSA-OAEP 封装 AES-256 会话密钥 │ → /api/crypto/handshake → sid（密钥仅内存，v1 secure.ts 原样） ├ 请求体 → 信封 {enc:1, n, p}（AES-256-GCM） ├ Authorization → ENC <nonce>:<payload>（内层 Bearer <access>）+ X-Session-Id ├ Accept-Language: 当前语言（zh-CN/en） ← B6 对应动作 ▼ 响应拦截（ADP 结构保留，判定改 Portal 语义） ├ 信封解密 → body {code, msg, data} ├ code === 200 → 返回 data（泛型 T） ← B1 后端适配后与 ADP 原生判定一致 ├ code === 1100 && 未重试 → 重新握手 → 原请求重试一次（_raw 留原始体） ├ HTTP 401 / code 1002|1003 && 有 refresh → silentRefresh()（并发去重）→ 重试一次 → 失败才 logOut ├ code === 1007 → 透传给登录页（不弹全局错误） └ 其它 → HttpError(msg, code)，showErrorMessage 可配（ADP 原生能力保留）
